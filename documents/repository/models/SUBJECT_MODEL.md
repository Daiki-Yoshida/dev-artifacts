# subjects の定義と構成

`documents/knowledge/subjects/` は、`records/` の内容を削ったり変換したりせずに、`artifacts/` として適切な構成に整理して揃えて置く場所である。`records → subjects → artifacts` のうち、`subjects/` が担うのは、同じ情報を配布対象の開発哲学・開発方法論の構成に沿って配置することである。

## 整理で扱う範囲

整理では、フォルダ・ファイル・見出しを設け、扱う内容をまとまりごとに配置できる。定義に付いた条件や例外、提案に対する応答や訂正など、一緒に読むことで意味が定まる内容は、その関係と前後が分かる形で保つ。要約、言い換え、結論だけの抜き出し、整理者による解釈の追加は行わない。

`subjects/` の本文・索引では、`records/` への参照と、record を出典とする引用を禁止する。リンク、パス、記録スレッド名・記録IDによる出典表示もこれに含む。原記録の文言は、整理対象の内容そのものとして置く。別の subject を典拠として参照したり、そちらへの誘導で内容を代用したりしない。

## 配置

| 場所 | 収めるもの |
| --- | --- |
| `dev-philosophy/` | 開発哲学。SERA開発哲学は、全体の索引と、SCB・EIC・RTC・AJFそれぞれのフォルダおよび索引を持つ。 |
| `dev-methodology/` | 開発方法論。個々の方法論を整理する際に、その内容に応じて下位構成を定める。 |

索引（`INDEX.md`）には、その階層に何がどの名前で配置されているかを示す。SERAの索引は四哲学を採用済みの番号順に並べる。

## 旧構成の扱い

旧構成の哲学本文・草案は構成を検討する目安に限る。旧版が record の添付や保存版に含まれていても、その本文を新しい subject に移植しない。旧草案が用いた原記録を整理する場合は、新形式の記録スレッドに収めた原記録の実体を使う。
