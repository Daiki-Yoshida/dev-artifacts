## 0．本体系の前提と読み方

<a id="chapter-0"></a>

<a id="d0-1"></a>
### D0.1 本体系の語彙と定義を基点とする

本体系を理解するときは、一般的な語彙の意味、既存の哲学・学術理論、一般的な論理体系、ソフトウェア開発理論や設計思想などを、本体系の定義より優先してはならない。本体系は、ここに定義された概念と、それらの間に成立する関係によって独自の体系を構成している。まず本体系の内部で各語彙が何を指し、他の概念とどのように結びついているかを捉える。

「主体」「欲求」「まとまり」「認識」「情報」「仮想」「契約」「契約の成立」「履行」「境界」「乖離」などの語を、日常語や他分野で一般的な意味へ安易に読み替えない。語の表面が同じでも、本体系で定義された意味と関係を優先する。既存理論に同じ語や似た概念があることは、本体系の概念がその理論と同一である根拠にはならない。

これは一般的な論理や推論を捨てることではない。**外部の語彙・理論・慣習を、本体系の定義を解釈するための上位基準として持ち込まない**ということである。論理的な整合性の検討や、定義からの推論は必要である。ただし、その推論は本体系で定義された概念と関係を出発点に行う。外部理論との比較が明示的に求められた場合は比較してよいが、本体系内部の定義・命題と外部理論の説明を混同しない。

<a id="d0-2"></a>
### D0.2 定義を孤立させず、体系内部の関係から理解する

本体系の概念は、個別の語義を覚えるだけでは理解できない。各概念が他の概念とどのように結びつき、何を同じものとして扱い、何を区別しているかを含めて理解する。

例えば、認識は一般的な知覚・受容を意味するのではなく、存在を撮影し、最初から命名・契約を伴って主体にとっての情報Pを成立させる行為である。撮影が曖昧であれば、その時点で伴う命名・契約も曖昧である。明確に言語化できることや、対象を正確に分類できることを、認識や命名・契約を伴う条件として後から追加しない。

同様に、契約を一般的な法律上の約束だけに読み替えたり、命名・定義・境界と契約を無関係な別工程に分解したりしない。契約の内容を定義すること、異なる存在との合意によって契約が成立すること、成立した契約が実態において履行されることは、本体系が既に区別している関係に従って扱う。語彙を細分化して別名を増やすことで理解したことにせず、既存の「契約」という概念と、その定義・成立・履行の関係を理解する。

ある問いが生じたときは、まず既存の定義・性質・理論から答えを導けないかを検討する。既存の命題を適用すれば答えられる問いを、新たな未解決論点として追加しない。ある事例への答えがすぐに思い浮かばないことと、本体系にその答えを導く概念が存在しないことは同じではない。

<a id="d0-3"></a>
### D0.3 主体とまとまりに相対的な定義を、外部の唯一の分類へ置き換えない

本体系では、同じ実体であっても、主体がどのまとまりとして捉えるかによって、異なる存在として定義され得る。したがって、対象が主体から独立して唯一の分類・名前・境界を持つことを前提にしてはならない。

例えば、時計という欲求・まとまりでスマートフォンを捉える主体にとっては時計として扱われ、スマートフォンというまとまりで捉える主体にとってはスマートフォンとして扱われる。同じ実体に複数のまとまりが成立し得ることは、分類の曖昧さや体系の欠陥を意味しない。何として扱うかは、主体・欲求・コンテキストに応じた定義による。

また、同じ物理的な個体が異なる主体を担うこともあり得る。異なる存在の関係を扱う際に、物理的個体が必ず異なることなどの厳格な条件を独自に追加しない。どの主体の立場から、どの主体との関係を扱っているかを明確にする。主体の違いを意識することと、契約成立に必要な合意を満たすことは区別する。

<a id="d0-4"></a>
### D0.4 欲求・定義・再定義を、外部から推測した完全性で評価しない

欲求と本質は同じ求められた意味を両側から捉える。本体系における欲求は、主体がその存在に何を求めるかという関係であり、主体が自覚できない「本当の欲求」を外部の観察者が推測し、それを主体の定義より上位の基準として置くものではない。

主体が現在の定義に違和感や不足を見出したときは、その主体の欲求へ立ち返り、既存のまとまりに固執せず定義を捉え直すことができる。日時計として時間を知ろうとするまとまりと、目印として迷わないためのまとまりが、より適切な時計塔というまとまりへ脱皮する例は、この捉え直しを示す。脱皮は、外部の観察者が隠れた完全解を発見することではなく、主体が欲求に立ち返り、現在の定義を区切り直すことである。

本体系は、最初から完全な認識・完全な定義・唯一の最適なまとまりが得られることを前提としない。認識の撮影は不完全・誤り得るものであり、曖昧な撮影にも、その曖昧さに応じた命名・契約を伴うまとまりが既に定義される。後の撮影や定義が過去と異なることはあり得る。完全性を外部から要求して欠陥探しを続けるのではなく、主体の認識・欲求・定義がどのように変化したかを、本体系の概念に沿って扱う。

<a id="d0-5"></a>
### D0.5 哲学の普遍階層と方法論の具体化を混同しない

本体系は、ここで定義する「まとまり」一般に対して普遍的に言及する。プログラム、フォルダ、組織、製品などの具体的な対象は、本体系の外にある特別な例外ではなく、普遍的な構造がそれぞれの領域に現れた対象である。

一方、具体的な実現方法・手順・検査方法・運用規則は、その領域の実態や制約に応じて方法論が扱う。例えば、合意をどのように形成するか、具体的にどのように分割・統合するか、どの検証手段を採るかは、具象に応じた方法論の責務である。普遍的な哲学の問いを、ソフトウェア開発の慣習や特定の実務手順で置き換えない。

哲学に普遍的な性質・理論・判断指針が含まれることを妨げない。指針であることだけを理由に方法論へ移さない。ただし、特定領域の具体的な実現規則まで哲学に持ち込まない。**哲学は普遍的な意味・関係・判断の方向を扱い、方法論はそれを各領域の具象において実現する。**

<a id="d0-6"></a>
### D0.6 理解・導出・不足・矛盾を区別する

本体系をレビューするときは、疑問や批判を提示する前に、既存の定義と他の節を照合し、その問いが既に答えられていないかを確かめる。特に、次の状態を混同しない。

- 本文に明示されており、そのまま答えられること。
- 複数の既存定義を接続すれば導出できること。
- 本体系の内部だけではまだ決まらず、Ownerによる判断が必要なこと。
- 定義同士に実際の矛盾があること。
- 具体的な実現方法が未定であり、方法論に委ねられていること。

問いが既存の概念から導出できる場合は、その導出を示す。単に一般的な理論と表現が異なることや、具体的な手順が本文に書かれていないことを、哲学上の欠落・矛盾として扱わない。反対に、既存定義から導出できない点や、実際に両立しない命題が見つかった場合は、無理に既存理論へ当てはめず、その箇所と理由を明示する。

レビューは、完全な認識や外部の絶対的な検査基準を前提にしない。主体が過去に撮影・定義した情報と、後に撮影し直して成立した情報が異なる場合、その差異を捉え、どの主体のどの定義・契約がどう変わったかを検討する。実務上の検査手段を新たな普遍条件として要求せず、必要な具体的検証は方法論の責務として扱う。

## 1．まとまりと定義

<a id="d1-1"></a>
### D1.1 まとまりの仮想性

現にある事象や実態について、どこを区切り、何を一つと数え、何として扱うかに、主体から独立した唯一のまとまりが与えられているわけではない。

同じ対象を、原子の集合、歯車やばねの集合、時計、時計塔として捉えられる。どのまとまりを採るかによって、その存在が何であるかも変わる。ここでいう「まとまり」は、主体が定義する仮想的な存在である。

**本体系における「認識」とは、主体が存在Pを撮影し、主体にとっての情報Pというまとまりを定義する行為そのものを指す。** ここでの「撮影」は、一般的な知覚・受容・観察の語義に還元しない。また、撮影してから別工程として命名・契約を追加するのでもない。認識の撮影は、その行為の時点で既に何らかの命名・契約を伴い、情報Pを成立させる。

**認識の撮影は、最初から完全で精密な定義を行うとは限らない。** 例えば、主体がリンゴを見て「あの赤いやつ」「赤いもの」「リンゴ」と捉えるとき、その捉え方の精度や具体性には差がある。しかし、曖昧な捉え方であっても、主体はその対象を何らかのまとまりとして命名・契約し、情報Pとして成立させている。後から撮影を深め、品種・状態・価格・期限などを捉え直すこともできる。認識の撮影は不完全・誤り得るものであり、実体を100%完全に表現することを保証しない。不完全さや誤りは、認識が起きず、命名・契約を伴わず、情報Pが定義されないことを意味しない。

**本体系における「仮想」とは、主体の中だけに存在するものを指す。** 主体の中にある情報Pや契約は仮想である。一方、紙に記された文書やPC上に保存されたデータは、主体の外部に記録された実体であり、仮想そのものではない。文書やデータが主体の内にある契約を表現していても、主体内の契約と、それを表現する外部の記録実体は同一ではない。外部記録を主体が撮影して捉えるときには、その記録実体について、主体の中に別の情報Pが成立し得る。

したがって、主体にとってのPとは、主体が認識の撮影によって定義した情報Pである。情報Pは、実体Pの固定された複製や、観察結果を保存しただけの記録ではない。主体がPを何として扱うかという命名・契約・境界を持つまとまりであり、主体による撮影・定義の変化に応じて変化し得る。実体Pが変化する場合だけでなく、実体Pが変化していなくても、主体が新たに撮影し直すことで情報Pが変わる場合がある。

**主体が実体に直接触れたり、熱さや味を体験したりすることと、その実体について認識の撮影を行うことは区別する。** 体感・実体験が起きていることを否定しない。ここで論じているのは、体感が起きた瞬間に実体が情報へ変質するということではなく、主体がその存在をまとまりとして捉え、思考・言及できる情報Pを成立させる行為である。

同じ実体Pに対しても、主体X・Y・Zが異なる撮影を行えば、情報X-P・情報Y-P・情報Z-Pは異なり得る。例えば、犬を一年観察して白黒交互に毛が生え変わる法則を捉えた主体Xにとっての情報X-Pは「白黒交互に毛が生え変わる犬」であり、白い状態を一日観察しただけの主体Yにとっての情報Y-Pは「白い犬」であり、白い状態を観察した後に赤い首輪を付けた主体Zにとっての情報Z-Pは「白くて赤い首輪を付けた犬」である。それぞれの情報Pは各主体にとって成立しており、単に情報量の大小や正誤の順位として同一化しない。

**情報Pと仮想は、独立した二つの存在階層でも、前者から後者へ進む二段階の工程でもない。** 情報Pは主体の中に成立するまとまりであり、その主体内にあるという存在のあり方を「仮想」と呼ぶ。情報Pを一般的な知識・データ・記録の集合として扱わない。また、紙やPC上に記録されたものは外部の実体であり、主体内の情報Pとは区別する。

無数のまとまりが存在し得ることと、まだ特定のまとまりが定まっていないことは両立する。白いキャンバスに絵を描くことと、黒く汚れた窓を拭いて模様を浮かび上がらせることは、その捉え方を説明する二つの比喩である。

**撮影の対象は実体に限らず、仮想的な存在や意味も含む。** 主体は、自分が抱くまとまりや仮想的な意味をも撮影し、捉え直すことができる。

まだ実現されていないまとまりも、具体的な構想の前から、曖昧な仮想として命名・契約を伴って成立し得る。主体がゲームXを開発したいと考え、構想を練る前から「なんとなくこういうゲーム」という概要をXに対して抱いているなら、その主体は既にその曖昧なまとまりへXという命名・契約を伴わせている。対応する実体の有無は、定義・契約の成立とは別の問いである。

<a id="d1-2"></a>
### D1.2 定義の一体性

何かを「これは時計である」と定義することは、そのまとまりを何として扱うかを定めることである。

その存在を何と呼ぶかという命名、その存在が何であるかという本質、その存在として引き受ける範囲という境界は、この定義と一体である。抽象は特定の具象を決めずにその意味を扱う側面であり、契約は他の存在に対して何として関わるかを規定する側面である。認識の撮影は、この定義を主体の中に成立させる行為であり、最初の撮影から既に命名・契約を伴う。ただし、撮影が不完全・誤り得ることと、まとまりが成立することは両立する。

**境界があるとは、その存在が他のものと区別され、一つの存在として確立されているということでもある。** Aという存在を命名し、契約として定義することは、Aの側だけを定めて終わるものではない。AをAとして定義することは、同時にAではない側（NotA）を定め、AとNotAの違いを明確にする。したがって、Aについて定義することは、NotAについて定義すること、そしてAとNotAの境界について定義することと同義である。**Aの定義は、AとNotAの差異と境界を同時に成立させる。**

ここでいうNotAは、Aの定義によって区別される否定側を示す関係的な表現であり、NotA全体が一つの別個のまとまりとして定義されることまで意味しない。NotAの側を一つの存在として扱う場合は、その存在についても別途、主体に応じた命名・定義が必要になる。

ここでいう境界は、まとまりの意味・本質と切り離された別種の線や壁ではない。何をその存在として扱うかを定めることが、その存在として含める範囲と含めない範囲を定める。責務・契約・構造・依存などの文脈で「境界」と述べるときは、この同じ境界が、それぞれの関係や階層においてどのように現れ、どのような役割を果たすかを説明している。これらを独立した境界の種類として増設するのではなく、境界の意味と、その境界が構造の中で果たす役割を区別する。

**定義の一体性とは、定義・命名・意味／本質・抽象・契約・境界を、一つの意味ある存在を定める営みの異なる側面として扱うことである。** 名前を付けてから後で意味を与える、という独立した工程へ分解しない。

**本体系でいう本質は、物理的な実態そのものではなく、主体が認識・定義した仮想的なまとまりに帰属する、その存在が何であるかという意味である。** 同じ陶器の実態を、ある主体は飲用容器としてのマグカップ、別の主体は植木鉢として捉え得る。両者が論じる本質は、それぞれの仮想的なまとまりに対するものであり、実態に備わる性質と、どの性質をまとまりの本質として定めるかは区別される。

この説明で「認識・定義」と並べるのは、認識が先に完成し、その後に定義を追加するという時間的・手続的な順序を示すためではない。個体について言及できるためには認識を介するということと、その個体をどの意味のまとまりとして定義するかということを、説明上区別している。認識内容のすべてが、定義済みのまとまりと同一であるわけでもない。

ここでいう命名は、単に文字列を貼ることに尽きず、何として認識・定義するかという意味を含む。認識の撮影は、主体が存在を何として捉えるかを定義する行為であり、撮影の時点で既に命名・契約を伴う。**「命名＝契約＝境界」は、命名・契約による定義がAとNotAの差異を同時に成立させることを示す。** 本質はAが何であるかという定義の意味であり、境界はその定義によってAとNotAが区別されることを表す。これらは後から独立に付加されるものではない。ここでいう定義・命名・契約の内容を定めることと、異なる存在との合意によって契約が成立すること、成立した契約が履行されることは、引き続き区別する。

名前は、その存在を何として扱うかを宣言する。時計として扱う間は時計としての意味を保ち、実態に偶然備わった機能を、理由なく時計の本質へ取り込まない。

この一体性と、異なる存在との合意による「契約の成立」は、別の問いとして接続する。契約そのもの・成立・履行の使い分けは [第3章](#chapter-3) で定める。

<a id="d1-3"></a>
### D1.3 抽象の高さと意味の方向

まとまりは、ミクロからマクロへ再帰的に捉えられる。時計の内部に機構、その内部に部品を見出すことも、時計を含む時計塔や街を捉えることもできる。一度選んだ隣接階層の間にも、別のまとまりを挿入できる。

また、同じ棒を支え、目印、日時計と捉えるように、同じ実態に対して異なる意味のまとまりを定義できる。抽象の高さを変える縦方向と、何として扱うかを変える横方向の両方がある。

この再帰性をフラクタル性と呼ぶ。階層間への挿入を実数の連続性にたとえる説明も、無数の区切り方を表す比喩として扱う。特定の数学的構造が証明されたという意味は与えない。

境界が対象とするのは、特定の具象そのものではなく、意味を持つ抽象的なまとまりである。**「時計」という命名が向かうのは、実体である一つの時計や、内部構造を未決定にした設計ではなく、「時刻が分かるもの」という本質を持つ仮想的なまとまりである。** その本質を定義することに、内部や実現方法という問いを立てる必要はない。ここで「内部を問わない」と述べるのは、実現方式を後から決めるために空欄を残すという意味ではない。そもそも「時刻が分かるもの」という本質を捉える問いに、内部構造という問いを持ち込む必要がないという意味である。

出典：S01 U2〜U8、S02 U1〜U7、S04 U2〜U3・U6、S05 U2、S10の第5・7・8部Owner発言。本質の帰属先と命名の意味はS10を踏まえた草案の補強案。[対応表](A3_PHILOSOPHY_REVIEW.md#traceability)

<a id="chapter-2"></a>
## 2．主体・欲求・責務

<a id="d2-1"></a>
### D2.1 個体と主体

主体は、ある関わりにおいて対象を捉え、定義し、判断する立場として扱う。同じ個体でも、PCを組み立てるときには組立者、PCを使うときには利用者として、異なる主体になる。

組立者にはCPUやGPUなどの契約が現れ、利用者にはPC全体の契約が現れる。同一個体の中でも、それぞれの主体の欲求・契約は独立して共存できる。

どの主体の定義かを特定することは、誰という個体かを示すことだけでは足りない。その関わりで何を求め、どの責務を担う立場なのかも含めて捉える。

主体の位置づけも時間とともに変わる。主体側と対象の実態側の双方から、適切な境界へ変化圧がかかる。

この区別により、契約の関係を担う主体の相違を、物理的な個体の相違だけへ限定しない。ただし、複数主体を認めること自体が、それらの間の合意まで保証するわけではない。成立については [D3.2](#d3-2) で扱う。

<a id="d2-2"></a>
### D2.2 欲求と責務

主体がその存在に何を求めるかが欲求であり、その欲求に応えることが、まとまりの背負う責務である。

「時刻を知りたい」という欲求に対しては時計を、「規格に合う構造を作りたい」という欲求に対してはねじやばねを、一つの存在として捉え得る。適切な命名には、その存在をどうあってほしいと捉えているかが反映される。

例えば、**「時刻を知りたい」という欲求と、「時刻が分かるもの」という本質は、同じ求められた意味を主体の側と、そのまとまりの側から述べたものである。** 欲求を述べる側と本質を述べる側で表現は異なるが、別々の対象を選んでいるのではなく、求めている意味と、その意味を持つ存在を同じ問いとして捉えている。欲求が本質を求めるのであり、欲求と定義を独立した二つの工程へ分解しない。

その本質を「時計」と名指し、無数に考え得る仮想的なまとまりの中から、その意味を持つ存在として定義する。これは、欲求に対して腕時計・日時計・スマートフォンといった実現候補を選ぶことではない。これらの語を持ち出す場合は、それぞれがどの主体・欲求・抽象階層において何のまとまりとして扱われているかを別途示す必要がある。単に方式や製品が複数あることは、「時刻を知りたい」＝「時刻が分かるもの」という本質の結合への反例にならない。内部構造や方式を決めなくてもよいという省略の話でもなく、その本質を定めること自体には内部という問いが要らない。

**その存在に何を求めるかを定めることと、その存在を何として見るかを定めることは、同じ問いである。** 欲求を固定された唯一の出発点として置き、その後から別の作業としてまとまりを選ぶ構成にはしない。ここで基準となるのは、その主体の立場とコンテキストで扱われている欲求である。主体が自覚していない「本当の欲求」を外部の観察者が推測し、主体の定義に代わる基準として持ち込まない。主体が現在の定義を捉え直すときは、現在の主体が何を求めているかへ立ち返り、必要なら欲求・まとまりの高さや範囲を捉え直す。

欲求そのものもフラクタルである。電話・メモ・時計・動画などの欲求を、単一の端末で便利になりたいという欲求に包含できる。一方、電話したいという欲求にも、話したい、離れた相手と関わりたいといった意味を見出せる。これは欲求が抽象の高さを持ち、より広い欲求と、その内側にある個別の欲求を異なるまとまりとして捉えられることを示す。異なる高さの欲求を並べたときに複数の本質が現れることは、同じ欲求と本質の結合が複数の実現候補へ分岐したこととは異なる。どの欲求を基点としているかは、主体とコンテキストに照らして捉える。

したがって、欲求と本質の結合は、あらゆる表現が一つの固定された語句や、唯一の具体的対象へ機械的に対応するという意味での一意性ではない。例えば「幸せになりたい」という広い欲求は、その主体がどの意味で幸せを求めているかに応じて、健康でありたい、安定して暮らしたい、人と良好な関係を築きたいなど、異なる高さ・まとまりの欲求として捉え直され得る。それぞれの欲求について、その欲求が求める意味と、その意味を持つ存在の本質は同じ問いである。複数の定義が見える場合は、同じ欲求の本質が曖昧に分岐したと即断せず、どの主体・コンテキスト・欲求のまとまりを基点としているかを確かめる。これは欲求と本質の結合を弱める条件追加ではなく、欲求自体のフラクタル性を適用した説明である。

ある主体の定義において責務の意味が定まることと、その契約が別の存在との間で成立すること、実態がその責務を果たすことは区別する。たとえば、時計を「時刻を示す存在」と定義しても、それだけで合意や時刻表示の実現を保証しない。これは責務に別の種類を追加するのではなく、**誰の定義か、どの関係で成立しているか、どの実態が対応するか**を、契約・成立・履行の三つの問いに分けるものである。

<a id="d2-3"></a>
### D2.3 責務の内包・分割・委譲

「時計塔を建設する」という責務は、時計を作る、壁を建てる、階段を設置するなどの下位責務を内包する。適切に分割した責務は、合わせて見たときに元の上位責務へ収束する。分割の数が増えること自体で、元の責務の意味が増えるわけではない。

上位の主体が下位責務を内包することと、自らすべての下位主体として定義・判断することは異なる。建設を統括する主体は職人の責務を認識していても、そのすべての判断を自分で行う必要はない。

同じ個体が時計の設計者と歯車の製造者を兼ねることもできる。歯車を市販品へ置き換える場合には、その製造を別の主体へ委譲できる。責務を認識すること、その主体として判断すること、別主体へ委譲することは書き分ける。

<a id="d2-4"></a>
### D2.4 基点主体と担い手

**基点主体とは、ある主体を担う存在が現在置かれているコンテキストにおいて、主軸となる直接的な欲求に対応する主体である。** その主体が成立させようとするまとまりを、当該開発のマクロ側の親として捉える。ここでの「基点」は、あらゆる存在を外側へたどった絶対的な最上位ではなく、現在の欲求と扱う範囲に対して相対的に選ばれる。

主体と、それを担う存在と、開発対象となるまとまりを区別する。ゲーム開発という主体、ゲーム制作部署という担い手、ゲームという開発対象がその例である。**担い手の「一つの存在」は、現実の一人の個体に限られない。** 部署・工場・組織など、複数の個体を含む集合体も一つのまとまりとして主体を担い得る。主体の責務上の包含関係と、担い手の物理的・組織的な包含関係は、必ずしも一致しない。

**集合的な担い手が主体を担う場合、その主体の認識は、その集団が事実上どの方向性を取っているかとして定まる。** 例えば、部署の統括責任者が主体の中で目標を決定し構成員へ通達すれば、その内容は部署主体の認識となり得る。一方、外部の資料に記録した内容が構成員へ伝わっていなければ、その記録は責任者個人の情報Pを表現する実体に留まり、部署主体の認識とはならない。構成員が記録とは別の内容を認識し、部署の行動がそちらへ向かうなら、既成事実としての部署主体の認識はそちらの内容になる。**この既成事実の認識と、記録された契約・実態との間にも乖離は生じ得る。** どの主体のどの契約との乖離かを特定する枠組みは、担い手が個体でも集合でも同じく適用される。

ゲーム開発という主体から見ればゲームステージ開発は内側の主体だが、ステージ開発を主軸とするコンテキストでは、ステージ開発主体自身を基点として捉えられる。また、ゲーム開発を包むゲーム販売・シリーズ販売・企業の事業という主体も見出せるが、それらが常に現在の基点になるわけではない。**より外側のまとまりが存在し得ることと、今そのまとまりを基点として選ぶことは別である。**

基点主体の選定は、欲求とまとまりの選定が同じ問いであることの具体化であり、将来も同じ位置に固定されるものではない。基点を選び直すことから、既存の下位契約を自動的に変更したとは推定しない。同じ物理的な個体が、異なるコンテキストで異なる主体を担う場合もある。その場合、異なる個体であることを別途証明するのではなく、どの主体の立場で、どの主体との契約関係を扱っているかを明確にする。

出典：S12 U1〜U2（「基点主体」はS12 A1の提案に対してU2で肯定され、コンテキストと直接的欲求による説明はU2でOwner自身が提示）、S02 U2〜U3、S04 U4〜U5。担い手の包含関係の違いと、選定と再定義の関係はS12 A1・A2を接続した編集案。[対応表](A3_PHILOSOPHY_REVIEW.md#traceability)

<a id="chapter-3"></a>
## 3．契約と内部自由

<a id="d3-1"></a>
### D3.1 契約の定義

**契約とは、主体が仮想側において、ある存在の名前＝本質＝境界を定め、その存在が自身以外の別の存在に対して、どのように自身を見せ、扱わせ、存在させるかを定義したものである。** この契約は、対応する対象の実体が既に存在している場合に限られない。主体の中に契約が存在し、対象の実体がまだ存在しない場合でも、契約内容やその本質が存在しないことにはならない。

契約は、その存在が何であるかと、他の存在に対してどう関わるものとしてあるかを含む。プログラミングのinterfaceという特定の表現形式には限定しない。関数のシグネチャや命名、各領域・各階層の規格なども、契約を表す形式になり得る。

形式を設けたことだけで、契約の成立や履行を満たしたとは扱わない。契約の内容を定義すること、異なる存在との関係において成立すること、実態がその契約に対応することは、混同してはならない。それぞれについて、次の二つの問いを分ける。

<a id="d3-2"></a>
### D3.2 契約の成立

**契約の成立とは、その契約が、対象となる存在とは異なる別の存在との合意のもとで形成されることである。**

契約自体と、契約を結ぶ存在・相手となる存在の定義は仮想側にあるため、契約成立という関係の意味も仮想側で扱う。ただし、これを合意の具体的な成立まで仮想側だけで完結するという意味にしてはならない。**合意は具象とセットである。** 異なる存在との間に契約が成立したと扱うには、具体的な対象・権限・表現・状況に結びついた合意が必要になる。合意を抽象的な内心の一致だけとして捉えず、どの存在同士が、何について、どのような具体的根拠・表現・権限のもとで合意しているかを、その領域に即して扱う。

ソフトウェアではインターフェイスの公開や仕様書、物理的なハードウェアでは団体等が定める規格、法律では権限を持つ主体による公布など、合意の具体的な現れ方は具象の領域に応じて異なる。これらは合意の具体化が各領域の対象・権限・表現に結びつくことを示す例であり、すべての領域に共通する一つの合意手順を示すものではない。法律の公布を例にする場合も、公布という語だけから合意当事者や法制度上の関係を一律に推定しない。具体的に誰が何をどの権限で定め、どのような関係が成立するかは、その制度・領域に即して扱う。具体的な形成・確認・運用方法を一律の手順として定めることは方法論の責務である。

合意・相互確証は一対一に限られず、一対多、多対多の関係を取り得る。契約内容が定義されていることと、異なる存在との間にその契約が成立していることを区別する。**契約の対象となる実体がまだ存在しないことだけを理由に、契約の成立を否定しない。** 例えば、まだ実体化されていないゲームについて、その開発者と開発を担う別の存在との間で契約を成立させることはあり得る。成立に必要なのはD3.2で定める異なる存在との合意であり、対象となる成果物の実体が先に完成していることではない。

「異なる存在」を常に別の物理的個人と同一視しない。同一個体が複数主体を担い、それぞれの欲求・契約が共存することは [D2.1](#d2-1) の区別によって扱える。しかし、同一個体か別個体かという事実だけで、合意の成立・不成立を決めない。

再定義により合意内容を変える場合、変更後の関係を、以前の内容についての合意だけから成立済みとは推定しない。変更後の内容が、その相手との合意に支えられているかを扱う。ただし、既存の合意が認める変更範囲に収まる場合まで、一律に新しい確認行為を要求するものではない。必要な判断範囲と内部自由の関係は [D6.3](#d6-3) へ接続する。

本体系が普遍階層で定義するのは、契約そのもの・成立・履行の意味と、それぞれの関係である。哲学が合意の具体的な成立手段を列挙しないことは、合意という関係を空語にすることではない。異なる存在との合意のもとで契約が成立するという意味を保ち、その関係をどのような文書・規格・公開・権限・手続で実現し確かめるかを、具象に即した方法論へ委ねる。**具体的な合意形成、相互確証、成立の確認や運用を適切に実現することは、開発方法論の責務とする。** 哲学側で具象に共通する実務手順・判定方法を一律に定めずとも、「定義したこと」と「合意のもとで成立したこと」の区別は維持される。

<a id="d3-3"></a>
### D3.3 契約の履行

**契約の履行とは、成立した契約の対象となった存在の実態が、現実においてその契約に定められた責務に対応している状態を表すことである。** ここでいう「表す」は、誰かが乖離の有無を検査・評価する行為そのものを履行と呼ぶ意味ではない。履行は、成立した契約と実態との対応状態を指し、その状態を認識し、情報として捉え、適合・乖離を判断する行為は別の営みである。

**乖離とは、定義された契約と対応する実態が一致しない状態を指す。** 契約内容と実態の適合・不適合を捉えることと、成立した契約の履行を捉えることは区別する。 まだ異なる存在との合意が成立していない段階でも、定義された契約内容と実態が対応しているかを述べることはできる。しかし、本体系でそれを契約の「履行」と呼ぶのは、契約が成立した後の関係である。成立前の適合は、成立済み契約の履行と同一視しない。

成立は、契約が異なる存在との合意のもとで形成された関係を扱い、履行は、成立した契約と実態との対応を扱う。合意が形成されていることによって、現実の実態の適合が自動的に保証されるわけではない。反対に、契約内容と実態がたまたま対応していることだけで、異なる存在との合意や契約成立があったことにもならない。

たとえば、時刻を示す契約が成立している時計でも、故障によってその契約に沿う時刻表示ができなくなることがある。その実態の変化が、合意された時計の意味を自動的に変更するわけではない。

この区別から、契約の内容、成立、履行を混ぜずに、どこに問題があるかを捉えられる。契約内容が定義されていないのか、異なる存在との合意が成立していないのか、成立した契約に実態が対応していないのかは、それぞれ異なる問題である。契約の対象となる実体がまだ存在しない場合も、契約内容や成立の有無を扱うことはできるが、その対象実体による履行はまだない。さらに、それらの状態を認識の撮影によって捉え、情報として扱う行為は、状態そのものとは区別される。

<a id="d3-4"></a>
### D3.4 内部自由の契約相対性

**内部自由の契約相対性とは、内部自由がある主体の定義・契約の規定しない内側について成立し、その自由の範囲が契約に応じて異なるという性質である。**

時計塔として扱う契約において、時計の方式を規定していなければ、機械式・デジタル式・映像表示のいずれでもよい。一方、機械部品による機構として定義した主体には、機械部品であることが意味に含まれる。それでも、その契約が材質を規定していなければ材質には自由が残る。

外の主体が内部を「見なくてよい」ことと、内部の主体に契約が必要であることは両立する。内部の自由を用いて下位の契約を作ることができ、その下位の契約にも自由な内側がある。

したがって、**下位のまとまりの再定義が、上位のまとまりに対しては同じ契約を履行する内部変更にとどまる場合がある。** 機械式からデジタル式への変更が内部機構の定義を変えても、時計塔としての契約を変えずに済む場合がその例である。上位の契約を再定義しなくてよいことと、変更される下位契約の合意や、契約に定められた変更条件まで不要になることは同じではない。

**内部自由は、契約上の自由であり、現実に選択可能な実現方法が複数存在することまで定義に含めない。** ある上位契約が内部の方式・材質・構造を規定していなければ、その点は上位契約によって制約されていない。しかし、物理的・技術的・制度的な条件によって、現実に選べる方式が一つに限られることはあり得る。その場合も、選択肢が一つしかないという事実によって、上位契約がその方式を規定していたことにはならない。反対に、上位契約が規定していないことだけから、実現可能性や他の契約との適合まで保証されるわけでもない。

また、ある主体の契約に規定されていない内側であっても、その内部に成立している下位契約や、他の存在との契約が制約を持つ場合がある。したがって、内部自由は、すべての関係から無条件に自由であるという意味ではなく、**どの主体のどの契約に対して、何が規定されていないか**に相対的である。実現可能性は実態・制約に即して別に捉え、下位や他の契約との関係はそれぞれの主体・契約に照らして扱う。

内部自由を、効率・生産性・変更容易性だけから説明しない。各存在が独立した意味を持ち、その内部が自由であるという構造から、結果として変更の局所化や交換の容易さが得られ得る。

<a id="chapter-4"></a>
## 4．相互作用と実態

<a id="d4-1"></a>
### D4.1 相互作用にも意味が定義される

まとまり同士の相互作用も、主体による仮想的な定義の対象になる。同じ音でも、ある主体には騒音、別の主体には警報としての関わりになる。その関わりも、空気の振動、装置の出力、危険の通知など、異なる高さと意味で捉えられる。

現実の実態間には、電気信号や音などの作用が生じる。その作用を何として利用するかという意味を定義して、利用可能な関係として扱う。

**定義なしには、新しい相互作用を成り立たせることはできない。** ここでは、既に起きている物理的作用一般の存在条件ではなく、新しい意味ある関わりを成立させることを述べる。

<a id="d4-2"></a>
### D4.2 定義・運用・実態の関係

主体の中にある定義・命名・契約・本質・境界は仮想であり、それらを表現する紙上の文書やPC上のデータは外部に存在する実体である。文書やデータが契約内容を表現していることと、主体の中にある契約そのものを同一視しない。文書を作成・保存したことによって、その文書が表現する契約内容が主体の中で自動的に定義されるとも限らない。文書を読み、その内容を主体が認識の撮影によって捉えたとき、主体の中にその文書についての情報Pが成立し得る。

**契約と実体の関係は、開発対象に限定されない。** ある主体が何らかの存在をまとまりとして定義するあらゆる場面で、その主体内の契約と、それに対応する実体との関係を扱い得る。時計・マグカップ・人物・組織・仕様書・開発環境・開発対象など、対象の種類によってこの普遍性は限定されない。契約と実体の関係は、ある対象に一度だけ適用されるのではなく、その対象を構成するまとまりや、その対象を表現する文書・媒体などにも、それぞれの主体と定義に応じて再帰的に成立し得る。

契約は実体に先行して存在し得る。主体の中に契約があっても、対応する実体がまだ存在しない場合がある。また、主体がまだ特定のまとまりとして撮影・定義していない実体が先に存在する場合もある。契約の存在、契約の成立、対応する実体の存在、契約の履行は、それぞれ別の問いであり、互いを自動的に含意しない。

定義された契約は、主体の行為や他の存在との相互作用を通じて実体に関わり、実体を成立・変更させ得る。**ここでいう運用とは、こうした定義に形作られた主体の行為・相互作用の流れであり、実体はこの運用を通じて定義と関わる。** ここで仮想側の定義が実体を直接・自動的に変えると主張しているのではない。定義と実体は同一ではなく、契約が存在・成立しただけで履行が保証されるわけでもない。

主体が契約と実体の対応を捉えるときも、その主体は認識の撮影を通じて対象をまとまりとして定義する。したがって、乖離についての主体の認識も、実体そのものを100%完全に写し取ったものではなく、不完全・誤り得る。**主体が乖離を認識したことと、実際に契約と実体の乖離が存在することは、同じではない。** 認識された乖離の情報が誤っている場合もあり得る。一方、認識が不完全であることは、契約と実体の対応や履行を扱えないという意味ではない。主体は認識の撮影によって得た情報をもとに、契約と実体の関係を捉え、必要に応じて撮影を深め、定義を見直す。

主体が実体に直接触れたり、作用や体感を経験したりすることと、その実体を認識の撮影によってまとまりとして捉えることは区別する。認識の撮影は実体そのものを思考へ直接移すことではなく、主体にとっての情報Pを成立させる。

定義しただけで実態がそのとおりになるわけではない。実態を変えずに仮想的なまとまりを捉え直すこともできる。逆に、実態が変わっても、仮想的な本質が自動的に変わるわけではない。

したがって、仮想的な定義と実態の対応を扱う必要がある。乖離を捉える際には、**どの主体が定義した、どの契約との乖離か**を特定する。乖離への対処は [第6章](#chapter-6) で扱う。

<a id="d4-3"></a>
### D4.3 共有実態と共通契約

同一の実態を、異なる主体がそれぞれ別の仮想的なまとまりとして扱える。Aが棒を日時計、Bが目印として契約している場合、Bが目印としての境界を保って照明を追加しても、Aから見ると影を利用できなくなり、日時計の契約との乖離が生じ得る。

同じ実態でも、どの契約から見るかによって適合・乖離は異なる。ここで「実態を契約から見る」という表現は、実態そのものを思考が直接掴むという意味ではない。主体は認識された情報を通じて実態を捉え、その情報を契約の意味と照らして関係を判断する。判断の対象となる実態と、判断に用いる認識内容を同一視しない。Bの契約がAの契約を直接書き換えたのではなく、変化した実態とそれぞれの契約との対応が異なる。

同じ実態に別々のまとまりを重ねることを避けられるなら、その方が競合を扱いやすい。資源などの事情から共有が必要な場合は、**初めから、その共通利用を契約として定義する**。双方が「日時計としても使える目印」として合意することが、その例になる。

変更の範囲を考えるときは、共有する実態に対して、どの契約上の関係が変わり、どの契約の履行に影響するかを区別する。一つの主体の契約内に収まる変更であることから、他の契約にも影響がないとは推定できない。共通利用の具体的な範囲は当該契約の内容によって定められる。合意形成・相互確証の具体的な運用は開発方法論が担う。

<a id="chapter-5"></a>
## 5．境界面理論

<a id="d5-1"></a>
### D5.1 問いは、幅のある再帰的構造をどのように区切るか

主体も欲求も責務も再帰的に捉えられるため、分割できるということだけでは、適切な構造は決まらない。同一個体がどの高さまで主体として関わるかも、合わせて問題になる。

境界面理論では、**どの幅を扱うかを定め、その内側をどの粒度と構造で区切るか**を考える。マクロ側の起点は[D2.4](#d2-4)の基点主体とその直接的な欲求によって相対的に定まり、ミクロ側の接点は各枝で異なる。「どこで分割を止めるか」はその中の局所的な判断として扱い、理論全体を一つの停止位置を探す問題に限定しない。

**境界を探る際には、基点主体が求める全体の抽象的な意味から、下位の意味と責務へ向けて境界を選定する。** 時計を求めるなら、時計の意味を基点として計測や表示などを考える。**具象の最小要素から上へ積み上げて、扱う意味や境界の起点を決める方向は採らない。** この指針は境界選定の探索方向に関するものであり、基点の捉え直しや[D6.3](#d6-3)の再定義時の判断範囲を禁止するものではない。

<a id="d5-2"></a>
### D5.2 境界の双璧

再帰的な分割の幅には、実践上、二つの異なる根拠による壁がある。これを**境界の双璧**と呼ぶ。

| 壁 | 幅を限定する根拠 | 例 |
| --- | --- | --- |
| マクロ側の壁 | 主体の欲求によって自然に限定される、今回作成・開発・規定したい親のまとまり | 時計を作る、ゲームを開発する、会社の規則を制定する |
| ミクロ側の壁 | 外部の存在へ委譲・依存でき、その内側を自ら構成せずに済むこと | 市販のばねやねじ、既存のプログラミング言語、既存の法律 |

マクロ側は今回の欲求の親を与え、ミクロ側は利用する存在への接続を与える。マクロ側に立つ基点主体は、現在のコンテキストに応じて選ばれる。ミクロ側の壁より下にも構造は続いており、その存在自体がなくなるわけではない。

双璧は絶対ではない。市販部品で足りなければ部品を自作し、既存のエンジンで足りなければエンジンの開発を引き受けることがある。時計への欲求に目印への欲求が合成されれば、親のまとまりが時計塔になることもある。

ここでの「委譲・依存」はOwnerが双璧を説明した文脈の語である。すべてを作業委託という一種類の関係に縮めない。また、ミクロ側の壁を、物理的に内部へ含まれる部品だけに限定しない。

市販部品の利用と既存制度を前提にした規則の制定では、存在同士の関係の種類は異なる。それでも、今回の主体がその存在自体をさらに構成・制定せずに利用し、自ら引き受ける範囲を限定する役割を持ち得る。関係の種類が異なることだけでは、双璧の定義に反しない。この説明から、すべての外部制約を無条件にミクロ側へ配置する規則までは導かない。

**ミクロ側の壁は、樹のすべての枝を同じ高さで横切る一本の線ではない。** ある枝では幹に近い場所で責務を委譲し、別の枝では内部を細かく構成してから依存先へ接続してよい。ゲーム開発ならステージ制作はその単位で委譲し、アルゴリズムの枝ではゲームエンジンの提供範囲より深く自ら実装し、プログラミング言語のランタイムを依存先としてもよい。**どこまで自ら担うかという壁の位置は枝ごとに異なり、必要に応じて枝ごとに見直せる。**

<a id="d5-3"></a>
### D5.3 幅と粒度を分けて考える

基点主体によるマクロ側の範囲と、各枝の委譲・依存先を踏まえて扱う幅を捉え、その内側をどの程度の粒度で分割するかを考える。粒度は等間隔でなくてよく、枝や場所ごとに粗密があってよい。

Ownerの数値例では、1000がマクロ側、100がミクロ側の壁である。

| 同じ1000〜100の幅 | 内側の区切り方 |
| --- | --- |
| 例A | 1000〜800を一つの区間とし、800・700・600・500・400と区切り、400から100の存在を直接利用する |
| 例B | 1000〜500を区切らず、500〜200を50刻みで区切る |

これらの数は抽象的な高さの説明用であり、行数・工数などの実測尺度ではない。**1000〜100は一つの幅の例示であり、樹全体でミクロ側の壁を同じ高さへ固定する意味ではない。** 枝ごとに異なる幅・粒度を選べる。考えられる中間階層をすべて独立させる必要はなく、あるまとまりから委譲・依存先へ直接接続することもできる。

幅を選ぶことと、その中の粒度を選ぶことは異なる判断である。幅を定めても粒度が一意に決まるわけではなく、粒度を検討する過程で壁を見直す必要が明らかになることもある。

<a id="d5-4"></a>
### D5.4 各階層自身の責務に立つ分割判断

分割を考えるときは、**その階層自身の欲求・意味・責務・構造に立って判断する。** その階層の主体も、自身の開発を扱うコンテキストでは基点主体となり得る。判断する立場と対象範囲は、外から見た絶対的な階層の高さではなく、現在の欲求・責務に即して捉える。個人開発という事情、全体の規模、現在の実装の密結合だけを理由として、必要な責務の独立を省略しない。

**契約による分割を既定として検討し、分割しないことには意味上・構造上の正当な理由を求める。** これは、双璧により選んだ範囲の内側をどのように区切るかについての普遍的な**規範的判断指針**である。単に無数のまとまりへ分割可能であるという事実だけから、分割の義務を論理的に証明したという意味ではない。

この指針の根底にあるのは、分割数を増やすことや変更容易性を最大化することではない。**それぞれの責務が、独立した意味と責務を持つ存在として成立し、その内側に自由を持てること自体に価値がある。** その独立性が成立する根拠は、単に構造的に切り離されていることではない。D1.2で述べたように、Aを一つの存在として命名・契約により定義することは、Aではない側（NotA）との差異と境界を同時に定める。すなわち、その存在が何であり何ではないかが定まり、他と区別された存在として確立される。この意味で、独立性は境界の確立に根拠を持つ。物理的に分離していることや、他の存在と一切関係を持たないことを意味しない。

契約によって、それまで曖昧だった複数の存在が、それぞれ何を担うかを確かにできるなら、まずその独立したまとまりを成立させる方向を検討する。変更容易性や交換可能性は、その独立性と内部自由が適切に成立した結果として得られ得るものであり、分割の唯一の目的ではない。

その際は、ある責務を独立したまとまりとして捉える意味があるか、そのまとまりが自らの契約として責務を引き受けられるか、分割したそれぞれの内側にも自由が成立するか、反対に一体として担うことに積極的な理由があるか、を検討する。例えば、ねじの頭部とねじ部を別々の責務・契約として扱う意味がなく、両者が互いの内部事情に深く依存して一つのねじとして責務を果たすなら、一体として扱う理由がある。一方、現在の実装が絡み合っているという事実だけでは統合の理由にならない。現在は密結合でも、意味・責務に照らして独立して成立させるべきまとまりがあるなら、分割を検討する。

これらは普遍的な判断観点であり、個別の分割位置を機械的に算出する公式ではない。具体的に何を独立させ、どの境界を設け、どの検証を行うかは、対象領域の実態・制約・担い手に応じて方法論が実現する。これらは判断の観点であり、必ず一つの順序で実施する工程や機械的な判定式ではない。

分割圧は、現在の実装の絡まりではなく、独立した責務を成立させるべき意味・構造から考える。一方、分割によりそれぞれが他方の内部事情へ過度に依存し、独立や内部自由の成立を阻害するなら統合圧を考える。現在のスパゲッティ構造を、そのまま統合の正当化に用いない。

契約によって意味と責務を定めること自体が一定の制約を伴うため、分割に制約が生じたことだけで、その制約を不当とは判断しない。**制約が独立した責務と内部自由の成立にどう関係するか**を問う。どの主体の、どの欲求・責務に対して分割や統合を正当化するかを明示することが判断の根拠となる。これらの判断原理と採用した規範的指針から、個別の分割位置が必然的に一意に決まるわけではない。

具体的な分割方法、分割・統合の評価、停止位置の選定、具体的な検証方法は、プログラミング、文書、組織、物理的な製品など各領域の実態・制約に応じて、開発方法論で実現する。ここで哲学が示すのは、独立した意味・責務・内部自由を持つまとまりとして成立させる価値と、分割を既定として検討する普遍的な判断指針であり、具体的な手順や実装判断の一律規則ではない。

<a id="d5-5"></a>
### D5.5 分割停止・委譲・外から見る範囲

その階層の内部をさらに独立した契約へ分けず、一体の内部として引き受けることが分割停止である。既に区切られた責務を別の主体へ任せる委譲とは区別する。

また、PC利用者がGPU内部の回路を直接扱う必要がないことは、回路の契約が存在しないことを意味しない。外の主体から見る必要がない範囲でも、内部の主体には固有の契約がある。

この違いを踏まえて、枝ごとに独立して区切る場所、一体として担う場所、委譲・依存先へ接続する場所を構成する。ある主体から見た委譲・依存先は、その存在を担う別の主体にとっては新たな基点となり得る。境界の永続的な最適性は保証できず、時間・欲求・契約の不備・実態との乖離に応じて再評価される。

判断原理があることは、すべての主体・対象・時点について唯一の最適分割が機械的に定まることを意味しない。個別の解が一意に出ないことと、判断に用いる哲学が存在しないことを区別する。

<a id="chapter-6"></a>
## 6．乖離と再定義

<a id="d6-1"></a>
### D6.1 起点は、仮想側と実態側の乖離である

変化しても、仮想側の定義と実態が乖離していなければ問題はない。内部自由の範囲で実態を変えながら、同じ契約のもとで扱い続けられる。

**主体が認識の撮影をし直し、過去に成立させた情報Pと異なる情報Pを成立させた場合、その差異を捉える。** 撮影は最初から不完全・誤り得るものであり、後の撮影が過去の撮影と異なることはあり得る。ここで必要なのは、過去と現在の情報Pの差異、およびそれぞれの主体・定義・契約を捉えることであり、認識のどちらかが実体を100%完全に表現していることを証明することではない。

**仮想側と実態側の乖離を認識した場合は、そのまま流さず、どの主体のどの契約に対する乖離かを特定して対処する。** 認識の撮影が不完全・誤り得ることは、撮影し直した情報Pの差異を捉えることや、契約と実体の対応を扱うことを無意味にしない。具体的な検査手段を一律の普遍条件として追加せず、必要な確認の方法は対象領域の方法論で扱う。これは、再定義という特定の対処を常に強制する意味ではない。

**仮想側と実態側が乖離した場合には、再定義することが望ましい。** これは、変化したという事実だけで再定義するという意味ではない。変化しても仮想側と実態側が乖離していなければ問題ではなく、乖離していない状態に修正できるなら再定義は必要ない。

再定義とは境界を区切り直すことであり、コストも影響も大きい。だからこそ境界は堅牢に保つ必要がある。

このとき、再定義は単に候補の一つとして中立に並べられるだけではなく、乖離に対して望ましい重要な対処である。ただし、既存の契約を維持したまま実態を修正し、仮想側と実態側が乖離していない状態へ戻せるなら、それでよい。**再定義が望ましいことと、すべての乖離に対して再定義だけを唯一の方法として強制しないことは両立する。** また、再定義を実態の修正が不可能な場合だけに限定する一律の順序も定めない。

再定義するか、既存の境界を維持して実態を修正するかを考える際には、現在の欲求・契約の意味・実態の変更可能性と影響を踏まえる。再定義が境界の区切り直しであり大きなコストと影響を伴うからこそ、境界を堅牢に保ち、乖離の有無を正確に捉える必要がある。

<a id="d6-2"></a>
### D6.2 乖離・再定義の検討につながる事情

Ownerが示したA/B/Cの分類は、仮想側・実態側で起こる変化や、定義と実態の対応を見直す契機を捉えるために用いる。**これらの事情が生じたことだけで、成立済みの契約と実態が必ず乖離したとは判断しない。**

| 分類 | 事情の例 |
| --- | --- |
| A：仮想側 | A-1：時間経過や主体の変化によって欲求が変わり、適切な契約・定義が変わる。A-2：当初の定義の不備が明らかになり、本来の欲求により沿った定義が見えてくる |
| B：実態側 | B-1：調整・変更の蓄積によって実態が定義から逸脱し始める。B-2：依存先が利用できなくなったり、実態側の不備により変更を迫られたりする |
| C：双方 | AとBが混成し、双方の事情が関係する |

これらは原因を尽くした一覧ではない。Aにおける「適切な定義が変わる」ことから、既存の成立済み契約が合意なく自動的に更新されるとは推定しない。

欲求の変化を扱うときにも、[D4.2](#d4-2) に従い、どの主体の、どの定義・契約との対応を見ているかを特定する。欲求・定義・契約・実態を一つの「変化」にまとめてしまうと、旧契約の履行状態と新しい欲求が求める本質との違いを失う。新しい欲求が生じたことは、新しい本質を定義する契機になり得るが、そのことだけで旧契約の意味や成立状態を遡って変更しない。成立済み契約と実態が整合している一方、現在求める新たな定義には同じ実態が適合しないことは両立する。

たとえば、分単位の時刻表示という契約を履行する時計に、秒単位の表示を新たに求めたとする。旧契約に対する履行、新しい定義と実態の適合、その新しい内容についての合意の成立は別の問いである。新たな要求だけを理由に旧契約を不履行と評価したり、まだ成立していない新契約を成立済みと扱ったりしない。

欲求と既存の定義の差を述べることは、直ちに契約と実態の不一致を述べることではない。欲求に対応する定義候補と実態の関係、成立済み契約と実態の関係を分けて記述する。依存先がその契約を履行していないことと、履行しているが今回求める能力には足りないことも、この区別で説明できる。

<a id="d6-3"></a>
### D6.3 再定義は境界を区切り直す行為である

再定義は、何を一つの存在として扱うかという境界を区切り直す行為である。名前＝本質＝境界が一体であるため、その存在として担うことや、他の存在からの扱われ方にも関わる。

区切り直しには大きなコストと影響がある。**だからこそ境界は堅牢に保つ。** 成立した意味を、内部の都合でなし崩しに変えない。その内側には、契約を履行する範囲で実態を変更する自由がある。

必要な区切り直しを判断するときは、まずその階層自身の主体で、境界を区切り直すべきかを考える。そこで扱えなければ親の主体へ、さらに必要ならその親へと判断する高さを上げる。

[D3.4](#d3-4) の内部自由により、下位で境界を区切り直しても、上位の意味と契約を維持できる場合には、その変更だけを理由に上位まで再定義する必要はない。上位の契約を維持できない場合は、その上位での再定義も検討する。ただし、これを「常に上位を不変にする」「常に最小変更を選ぶ」という別の規則にはしない。

判断の高さを上げることと、変更される契約関係において合意を扱うことは区別する。必要な範囲は、物理的な個体数や親子関係だけでなく、どの契約内容が変わるか、どの関係の履行に影響するかに照らして考える。上位の再定義が不要でも、下位の契約や共有実態を介する別の契約まで無関係になるわけではない。

変更後の合意の位置づけは [D3.2](#d3-2)、共有実態への影響は [D4.3](#d4-3) に従う。合意形成・相互確証の具体的な運用や権限の配置は、開発方法論で扱う。

<a id="d6-4"></a>
### D6.4 欲求への立ち返りと定義の脱皮

既存の名前や実現方法を保持するだけでなく、その存在に何を求めていたかへ立ち返ることができる。

Aが日時計として使いたいのは時刻を知るためであり、Bが目印として使いたいのは迷わないためである。日時計や棒という既存のまとまりに拘束されず、時計塔という別の本質へ脱皮できる。電話からスマートフォンへという例も、新しい意味と契約を見出すこととして捉えられる。

ここでの脱皮は、主体が自覚していない隠れた欲求を第三者が推測し、正解として提示することではない。現在の主体が既存のまとまりや実現形態に固執せず、自身の欲求へ立ち返り、その欲求をどの高さ・範囲で捉えるかを見直して、より適切なまとまりを定義し直すことである。最初の定義が完全であることを要求せず、定義の不完全さや変化を前提に、主体が欲求と定義を捉え直せることを含む。

脱皮には、同じ形に新しい名前を付けることだけでなく、まとまりの解体・再構成も含む。欲求自体にも抽象の高さがあり、時計塔はその一つの具体例である。

定義の捉え方が横へ移ったときは、その位置で、扱う幅と内側の境界を再び考える。新たな欲求や依存可能性によって、双璧の位置が変わることもある。現在の境界選定に、将来のあらゆる再定義を同時に織り込む必要はない。

再定義の前後で「同じ存在か」を問う場合にも、どの主体が、どのまとまりの、何の意味を同じとして扱うかを特定する。同じ実態や履歴を指すことは同じ定義を保つことを保証せず、ある定義が変わることも、別のまとまりにおける連続性がすべて失われることを意味しない。

新しい定義を設けることだけで、旧契約の終了・継承・改訂が自動的に決まるわけではない。別のまとまりとして旧契約を維持する構成もあり得る。個別の継続・変更・終了は、その契約の内容と関係、合意に即して扱う。すべての再定義に一律の同一性や承継処理を追加しない。
