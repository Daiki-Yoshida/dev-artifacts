**第1哲学：責務範囲「主体」、真名「主体と契約と境界の哲学」、略名「SCB哲学」。役割は、あらゆる存在に対する思考の根源。** 本文はStage 2-A-3の編集用草案。[2026-11-24の名称・責務範囲の採用判断](../../../knowledge/records/2026-11-24-scb-rtc-naming-and-responsibility/RECORD.md)に基づき、主体を責務範囲とし、根源を体系全体に対する役割として位置づける。略名SCBは**Subject / Contract / Boundary**の頭文字である。既存の概念定義・責務境界・章名・指針を引き継ぎ、本文の説明・章構成は引き続き吟味する。

本体系は、**主体が何を一つの存在として捉え、その存在が何であり、何を担い、他の存在とどう関わるかを定義する体系**である。認識・まとまり・命名・本質・契約・境界の関係を基礎に、主体の欲求と責務、契約の成立と履行、内部自由、分割と統合、乖離と再定義を扱う。

存在や関係を意味あるまとまりとして成立させ、その境界を捉えるための基礎を担う。他の三体系も、自身の対象・主体・責務・境界を捉える際に、この定義を基礎とする。四体系のまとまりと相互関係は[体系構成](A3_PHILOSOPHY_SYSTEMS.md)を参照する。

**本体系そのものを原則とし、内部の判断指針はそれぞれの意味と役割で扱う。** 内部の指針に独立した原則名や英語略称は設けない。この位置づけは[Ownerの判断](../../../knowledge/records/2026-11-14-contract-boundary-principle-unification/RECORD.md)による。用語の入口は[ユビキタス言語](A3_UBIQUITOUS_LANGUAGE.md)、原文と編集判断の対応・採否の経緯は[レビュー資料](A3_PHILOSOPHY_REVIEW.md)に置く。過去の原文はrecords、本文の改訂過程はGit履歴から辿る。

## 0．本体系の前提と読み方

<a id="d0-1"></a>
### D0.1 本体系の語彙と定義を基点とする

本体系は、ここに定義された概念と、それらの間に成立する関係によって構成される。まず「主体」「欲求」「まとまり」「認識」「情報」「仮想」「契約」「成立」「履行」「境界」「乖離」が何を指し、互いにどう結びつくかを捉える。

日常語や他分野と同じ語を用いていても、意味の基準は本体系の定義にある。既存の哲学・学術理論、ソフトウェア開発理論や慣習との比較を行うときは、双方の定義を明らかにして比較する。

論理的な整合性の検討や定義からの推論も、本体系の概念と関係を出発点に行う。外部理論の語義を上位基準として本体系を読み替えることと、定義された意味の整合性を検討することは区別する。

<a id="d0-2"></a>
### D0.2 体系内部の関係から理解する

各概念は、他の概念との結びつき、同一として扱う側面、区別する関係を含めて理解する。

認識は、存在を撮影し、その行為の時点から命名・契約を伴って主体にとっての情報Pを成立させることである。曖昧な撮影には、その曖昧さに応じた命名・契約が伴う。対象の正確な分類や明確な言語化は、既に成立した認識をさらに捉え直す際にも行われる。

定義・命名・本質・抽象・契約・境界は、一つの存在を定める営みの異なる側面である。その契約の内容を定めること、異なる存在との合意によって契約が成立すること、成立した契約が実態において履行されることは、それぞれの関係に即して捉える。

問いへの答えを検討するときは、既存の定義・性質・理論を接続して導ける範囲を確かめる。新しい用語や論点を設ける必要性も、その確認に基づいて判断する。

<a id="d0-3"></a>
### D0.3 主体とまとまりに相対的な定義を捉える

同じ実体でも、主体がどのまとまりとして捉えるかによって異なる存在として定義され得る。同じスマートフォンの実体を、時計という欲求・まとまりで捉える主体は時計として扱い、スマートフォンというまとまりで捉える主体はスマートフォンとして扱う。何として扱うかは、主体・欲求・コンテキストに応じた定義による。

また、同じ物理的個体が異なる主体を担う場合もある。存在同士の関係を扱う際は、どの主体の立場から、どの主体との関係を扱うかを特定する。主体の相違と物理的個体の相違、主体の区別と契約成立に必要な合意は、それぞれ別の問いである。

<a id="d0-4"></a>
### D0.4 主体の欲求と現在の定義に立って捉え直す

欲求と本質は、同じ求められた意味を主体とまとまりの両側から捉える。基準となる欲求は、その主体がその存在に何を求めているかにある。外部の観察者が推測した、主体も自覚していない「本当の欲求」を上位基準として置かない。

主体が現在の定義に違和感や不足を見出したときは、自身の欲求に立ち返り、まとまりを捉え直せる。時刻を知るための日時計と、迷わないための目印から、時計塔というまとまりへ脱皮する例は、この捉え直しを示す。

認識の撮影は不完全・誤り得るものであり、曖昧な撮影にもまとまりは成立する。後の撮影や定義が過去と異なる場合は、主体の認識・欲求・定義の変化を捉える。本体系は、完全な初期認識や唯一の最適なまとまりを前提とせず、主体が欲求と定義を捉え直せることを含む。

<a id="d0-5"></a>
### D0.5 哲学の普遍階層と方法論の具象を捉える

本体系は、ここで定義する「まとまり」一般に共通する意味・関係・判断の方向を扱う。プログラム、フォルダ、組織、製品などは、その普遍的な構造が各領域に現れた対象である。

方法論は、それを各領域の具象において実現する。合意の具体的な形成方法、分割・統合の実施方法、検証手段、運用規則は、対象領域の実態と制約に応じて扱う。

普遍的な性質・理論・判断指針は哲学の内容に含む。哲学と方法論の区別は、指針という形式の有無ではなく、そこで規定する意味が普遍階層にあるか、領域固有の実現を定めているかによる。

<a id="d0-6"></a>
### D0.6 理解・導出・不足・矛盾を区別する

レビューでは、問いに関係する定義と各節を照合し、次の状態を区別する。

- 本文に明示されており、そのまま答えられること。
- 複数の既存定義を接続すれば導出できること。
- 本体系の内部だけではまだ決まらず、Ownerの判断が必要なこと。
- 定義同士に実際の矛盾があること。
- 具体的な実現方法が未定であり、方法論に委ねられていること。

既存概念から答えられる場合は導出を示し、定義が不足する点や両立しない命題がある場合は、その箇所と理由を明らかにする。外部理論との表現の違いや実務手順の未記載は、それぞれ比較や方法論の問いとして扱う。

レビューする主体の認識も不完全・誤り得る。過去と現在の撮影・定義の差異を捉え、どの主体のどの契約がどう変わったかを検討する。必要な具体的検証は、その対象領域の方法論で実現する。

## 1．まとまりと定義

<a id="d1-1"></a>
### D1.1 まとまりの仮想性

同じ対象を、原子の集合、歯車やばねの集合、時計、時計塔として捉えられる。どこを区切り、何を一つと数え、何として扱うかによって、その存在の意味が変わる。**まとまりは、主体が定義する仮想的な存在である。**

**認識とは、主体が存在Pを撮影し、主体にとっての情報Pというまとまりを定義する行為そのものである。** 撮影の時点で命名・契約が伴い、情報Pが成立する。「撮影」はこの行為を指す本体系の語であり、一般的な知覚・受容・観察の語義へ還元しない。

撮影の精度や具体性には差がある。リンゴを「あのなんか赤いやつ」「赤いもの」「リンゴ」と捉える場合、それぞれの曖昧さや具体性に応じたまとまりが命名・契約されている。対象の正確な分類や明確な言語化に至っていなくても、その認識には既に情報Pが成立している。後から品種・状態・価格・期限などを捉え直し、撮影を深めることもできる。

**認識の撮影は不完全・誤り得るものであり、実体を100%完全に表現することを保証しない。** その不完全さと、撮影によって命名・契約を伴うまとまりが成立することは両立する。

**仮想とは、主体の中だけに存在するものを指す。** 主体内の情報Pや契約は仮想である。紙に記された文書やPC上に保存されたデータは、主体の外部に記録された実体である。主体内の契約と、それを表現する記録実体は異なる存在であり、主体がその記録を撮影すれば、記録についての情報Pが主体の中に成立し得る。

情報Pは、主体がPを何として扱うかという命名・契約・境界を持つまとまりである。実体Pの固定複製や、観察結果を保存した記録とは区別する。実体Pの変化によっても、実体Pが変わらず主体が撮影し直すことによっても、情報Pは変化し得る。

同じ実体Pについて、主体Xが一年観察して「白黒交互に毛が生え変わる犬」、主体Yが白い状態を一日観察して「白い犬」、主体Zが白い状態の観察後に赤い首輪を付けて「白くて赤い首輪を付けた犬」と捉えたとする。それぞれの情報Pは各主体にとって成立するまとまりであり、情報量や正誤の順位だけで一つに同一化できない。

情報Pが主体内にあるという存在のあり方を「仮想」と呼ぶ。両者は別々の存在階層や前後の工程を表さない。主体が熱さや味を直接体験することは、その体験について思考・言及できる情報Pを成立させることと区別する。認識の撮影によって、実体そのものが情報へ変質するわけではない。

撮影の対象には実体に加えて、主体が抱く仮想的な存在や意味も含まれる。主体は自身のまとまりを撮影し、捉え直すことができる。ゲームXを開発したいと考え、具体的な構想の前から「なんとなくこういうゲーム」と抱く場合も、その曖昧なまとまりにはXという命名・契約が伴う。定義されたまとまりと、対応する実体の有無は別の問いである。

無数のまとまりが存在し得ることと、まだ特定のまとまりが定まっていないことは両立する。白いキャンバスに絵を描くことと、黒く汚れた窓を拭いて模様を浮かび上がらせることは、その捉え方を説明する二つの比喩である。

<a id="d1-2"></a>
### D1.2 定義の一体性

何かを「これは時計である」と定義することは、そのまとまりを何として扱うかを定めることである。命名は何として呼び扱うか、本質はその存在が何であるか、抽象は特定の具象を決めずにその意味を扱う側面、契約は他の存在に対してどう関わるか、境界はその存在として引き受ける範囲を表す。

**定義の一体性とは、定義・命名・意味／本質・抽象・契約・境界を、一つの意味ある存在を定める営みの異なる側面として扱うことである。** 認識の撮影はこの定義を主体内に成立させる行為であり、最初の撮影から命名・契約を伴う。名前を付けてから別工程で意味や境界を加える関係ではない。

**Aを命名・契約として定義することは、同時にAではない側（NotA）との差異と境界を定め、Aを他と区別された一つの存在として確立することである。** Aについて定義すること、NotAについて定義すること、AとNotAの境界を定義することは、この関係において同義である。NotAはAの定義によって区別される否定側を示す。NotA全体を別の一つの存在として扱う場合は、そのまとまりについても主体に応じた命名・定義が必要になる。

境界は、まとまりの意味・本質を定めることにより成立する。責務・契約・構造・依存の文脈では、この同じ境界が各関係・階層で果たす役割を説明する。境界の意味と構造上の役割を区別し、それぞれを別種の境界として増設しない。

**本質は、主体が認識・定義した仮想的なまとまりに帰属する、その存在が何であるかという意味である。** 同じ陶器の実態を、ある主体は飲用容器としてのマグカップ、別の主体は植木鉢として捉え得る。実態に備わる性質と、どの性質をまとまりの本質として定めるかは区別する。

認識によって個体について言及できることと、その個体をどの意味のまとまりとして扱うかは、説明上捉え分けられる。その個体について認識する内容すべてを、ある一つのまとまりの本質として定義するわけではない。時計として扱う間は時計としての意味を保ち、実態に偶然備わった機能を、理由なく時計の本質へ取り込まない。

「命名＝契約＝境界」は、文字列を付けることだけでなく、意味ある存在を定めることとA／NotAの差異が一体であることを表す。契約の内容を定めること、異なる存在との合意によって契約が成立すること、成立した契約が履行されることの関係は、[第3章](#chapter-3)で扱う。

<a id="d1-3"></a>
### D1.3 抽象の高さと意味の方向

まとまりは、ミクロからマクロへ再帰的に捉えられる。時計の内部に機構、その内部に部品を見出すことも、時計を含む時計塔や街を捉えることもできる。一度選んだ隣接階層の間にも、別のまとまりを挿入できる。

同じ棒を支え、目印、日時計と捉えるように、同じ実態に異なる意味のまとまりを定義できる。抽象の高さを変える縦方向と、何として扱うかを変える横方向の両方がある。この再帰性をフラクタル性と呼ぶ。階層間への挿入を実数の連続性にたとえる説明も、無数の区切り方を表す比喩である。

**「時計」という命名が向かうのは、「時刻が分かるもの」という本質を持つ仮想的なまとまりである。** この本質を定める問いは、実体である一つの時計や内部構造を対象とする問いとは異なる。「内部を問わない」とは、実現方式の決定を後回しにするための空欄ではなく、その本質を捉えることに内部構造の問いが要らないという意味である。

<a id="chapter-2"></a>
## 2．主体・欲求・責務

<a id="d2-1"></a>
### D2.1 個体と主体

主体は、ある関わりにおいて対象を捉え、定義し、判断する立場として扱う。同じ個体でも、PCを組み立てるときには組立者、PCを使うときには利用者として、異なる主体になる。

組立者にはCPUやGPUなどの契約が現れ、利用者にはPC全体の契約が現れる。同一個体の中でも、それぞれの主体の欲求・契約は独立して共存できる。

どの主体の定義かを特定するには、個体の同定に加え、その関わりで何を求め、どの責務を担う立場かを捉える。主体の位置づけは時間やコンテキストとともに変わり、主体側と対象の実態側の双方から適切な境界へ変化圧がかかる。

主体の相違と物理的個体の相違を区別する。また、複数の主体があることと、その間に契約が成立していることも別の問いである。成立は[D3.2](#d3-2)で扱う。

<a id="d2-2"></a>
### D2.2 欲求と責務

主体がその存在に何を求めるかが欲求であり、その欲求に応えることが、まとまりの背負う責務である。「時刻を知りたい」という欲求に対して時計を、「規格に合う構造を作りたい」という欲求に対してねじやばねを、一つの存在として捉え得る。適切な命名には、その存在をどうあってほしいと捉えているかが反映される。

**「時刻を知りたい」という欲求と「時刻が分かるもの」という本質は、同じ求められた意味を主体の側とまとまりの側から述べたものである。** その存在に何を求めるかと、何として見るかは同じ問いであり、その本質を「時計」と名指す。欲求と定義を独立した二工程へ分解しない。

本質を定める問いと、腕時計・日時計・スマートフォンなどの実現候補を選ぶ問いは異なる。それらを例として扱う際は、どの主体・欲求・抽象階層で何のまとまりとして捉えているかを示す。「時刻が分かるもの」という本質を定めること自体には、内部や実現方式の問いは要らない。

基準となるのは、その主体の立場とコンテキストで扱われている欲求である。現在の定義を捉え直すときは、その主体が何を求めているかへ立ち返り、必要に応じて欲求・まとまりの高さや範囲を捉え直す。外部の観察者が推測した、本人も自覚していない「本当の欲求」をその上位に置かない。

欲求そのものもフラクタルである。電話・メモ・時計・動画などの欲求を、単一の端末で便利になりたいという欲求に包含できる。電話したいという欲求にも、話したい、離れた相手と関わりたいという意味を見出せる。異なる高さにある欲求は、それぞれのまとまりとして捉える。

欲求と本質の結合は、一つの固定された語句や唯一の具体的対象への機械的対応を意味しない。「幸せになりたい」という広い欲求も、主体が求める意味に応じて、健康、安定した暮らし、良好な関係などの異なる高さ・まとまりへ捉え直せる。それぞれについて、求める意味とその意味を持つ存在の本質は同じ問いである。複数の定義を扱う際は、基点となる主体・コンテキスト・欲求のまとまりを確かめる。

責務の意味を定義すること、別の存在との間で契約が成立すること、実態がその責務を果たすことは区別する。時計を「時刻を示す存在」と定義した場合も、合意や時刻表示の実現はそれぞれの関係に即して捉える。**誰の定義か、どの関係で成立しているか、どの実態が対応するか**が、契約・成立・履行を捉える三つの問いとなる。

<a id="d2-3"></a>
### D2.3 責務の内包・分割・委譲

「時計塔を建設する」という責務は、時計を作る、壁を建てる、階段を設置するなどの下位責務を内包する。適切に分割した責務は、合わせて見たときに元の上位責務へ収束する。分割の数が増えること自体で、元の責務の意味が増えるわけではない。

上位の主体が下位責務を内包することと、自らすべての下位主体として定義・判断することは異なる。建設を統括する主体は職人の責務を認識していても、そのすべての判断を自分で行う必要はない。

同じ個体が時計の設計者と歯車の製造者を兼ねることもできる。歯車を市販品へ置き換える場合には、その製造を別の主体へ委譲できる。責務を認識すること、その主体として判断すること、別主体へ委譲することを、それぞれの関係として捉える。

<a id="d2-4"></a>
### D2.4 基点主体と担い手

**基点主体とは、ある主体を担う存在が現在置かれているコンテキストにおいて、主軸となる直接的な欲求に対応する主体である。** その主体が成立させようとするまとまりを、当該開発のマクロ側の親として捉える。基点は、現在の欲求と扱う範囲に対して相対的に選ばれる。

主体、それを担う存在、開発対象となるまとまりを区別する。ゲーム開発という主体、ゲーム制作部署という担い手、ゲームという開発対象がその例である。個人に加え、部署・工場・組織などの集合体も一つのまとまりとして主体を担い得る。主体の責務上の包含関係と、担い手の物理的・組織的な包含関係は、それぞれに捉える。

**集合的な担い手が主体を担う場合、その主体の認識は、その集団が事実上どの方向性を取っているかとして定まる。** 部署の統括責任者が目標を決めて構成員へ通達すれば、その内容は部署主体の認識となり得る。外部資料に記録した内容が構成員へ伝わっていない場合、その記録は責任者個人の情報Pを表現する実体に留まる。構成員が別の内容を認識し部署の行動がそちらへ向かうなら、既成事実としての部署主体の認識はそちらの内容となる。

この集団の認識と、記録された契約・実態との間にも乖離は生じ得る。担い手が個体でも集合でも、どの主体のどの契約との乖離かを特定して扱う。

ゲーム開発を基点とすればステージ開発は内側の主体となり、ステージ開発を主軸とするコンテキストでは、その主体自身が基点となる。ゲーム販売・シリーズ販売・企業の事業という外側の主体も見出せるが、どれを現在の基点とするかは直接的な欲求とコンテキストによる。

基点主体の選定は、欲求とまとまりの選定が同じ問いであることの具体化であり、時間とともに選び直せる。既存の下位契約の変更は、その内容と合意に即して別に扱う。同じ物理的個体が複数の主体を担う場合も、どの主体の立場でどの主体との関係を扱うかを明確にする。

<a id="chapter-3"></a>
## 3．契約と内部自由

<a id="d3-1"></a>
### D3.1 契約の定義

**契約とは、主体が仮想側において、ある存在の名前＝本質＝境界を定め、その存在が自身以外の別の存在に対して、どのように自身を見せ、扱わせ、存在させるかを定義したものである。** 対応する対象の実体がまだ存在しない場合にも、主体の中に契約内容や本質は存在し得る。

契約は、その存在が何であるかと、他の存在に対してどう関わるものとしてあるかを含む。プログラミングのinterface、関数のシグネチャや命名、各領域・階層の規格などは、その内容を表す形式になり得る。

契約の内容を定義すること、異なる存在との関係において成立すること、実態がその契約に対応することは、それぞれの問いとして扱う。表現形式を設けたことだけから、成立や履行を満たしたとは判断しない。

<a id="d3-2"></a>
### D3.2 契約の成立

**契約の成立とは、その契約が、対象となる存在とは異なる別の存在との合意のもとで形成されることである。**

契約と、契約を結ぶ存在・相手となる存在の定義は仮想側にあり、契約成立という関係の意味も仮想側で扱う。**合意は具象とセットである。** どの存在同士が、何について、どの具体的な対象・権限・表現・状況に結びついて合意しているかを、その領域に即して扱う。抽象的な内心の一致だけで、具体的な合意の成立まで完結するものではない。

ソフトウェアのインターフェイス公開や仕様書、ハードウェアについて団体等が定める規格、法律について権限を持つ主体が行う公布など、合意の現れ方は具象の領域によって異なる。これらは各領域で対象・権限・表現が具体化される例である。たとえば法律の公布を扱う際にも、どの主体が何をどの権限で定め、どの関係が成立するかは、その制度に即して捉える。

合意・相互確証には、一対一、一対多、多対多の関係がある。対象となる成果物がまだ実体化されていなくても、その開発者と開発を担う別の存在との間に、開発するゲームについて契約を成立させることはあり得る。成立に必要なのは異なる存在との合意であり、成果物の完成が先行することではない。

同一個体が複数主体を担う場合も、[D2.1](#d2-1)に従って関係を捉える。物理的に同じ個体か別個体かと、当該主体間に合意が成立しているかは別の問いである。

再定義によって合意内容を変える場合は、変更後の内容が相手との合意に支えられているかを扱う。既存の合意が認める変更範囲に収まる場合と、その範囲を超えて内容を変える場合を区別する。既存の合意が認める範囲内の変更は、その合意に基づいて扱い、一律に新たな確認行為を要求しない。必要な判断範囲と内部自由の関係は[D6.3](#d6-3)へ接続する。

哲学は、契約が異なる存在との合意のもとで成立する意味を定める。**合意形成、相互確証、成立の確認や運用を、各領域の文書・規格・公開・権限・手続によって適切に実現することは、開発方法論の責務である。** この責務境界により、普遍的な意味を保ったまま、具象に応じた成立手段を扱える。

<a id="d3-3"></a>
### D3.3 契約の履行

**契約の履行とは、成立した契約の対象となった存在の実態が、現実においてその契約に定められた責務に対応している状態を表すことである。** 履行は契約と実態との対応状態であり、その状態を認識し、検査・評価する行為とは区別する。

**乖離とは、定義された契約と対応する実態が一致しない状態である。** 合意が成立する前にも、定義された契約内容と実態の適合・不適合は述べられる。本体系で「履行」と呼ぶのは、契約が成立した後の対応関係である。

成立は異なる存在との合意のもとで形成された関係を、履行は成立した契約と実態との対応を扱う。合意が形成されていても実態が適合しない場合や、実態がたまたま定義に適合していても合意は成立していない場合がある。

時刻を示す契約が成立している時計でも、故障によってその責務を果たせなくなることがある。その場合、合意された時計の意味を保ったまま実態に乖離が生じている。

この区別により、契約内容の定義、異なる存在との合意、成立した契約に対する実態の対応のどこに問題があるかを捉えられる。対象実体がまだ存在しない場合も契約内容や成立の有無は扱えるが、その実体による履行はまだない。それらの状態について主体が認識した情報と、状態そのものも区別する。

<a id="d3-4"></a>
### D3.4 内部自由の契約相対性

**内部自由の契約相対性とは、内部自由がある主体の定義・契約の規定しない内側について成立し、その自由の範囲が契約に応じて異なるという性質である。**

時計塔として扱う契約が時計の方式を規定していなければ、機械式・デジタル式・映像表示のいずれでもよい。機械部品による機構として定義した主体には、機械部品であることが意味に含まれる。その契約が材質を規定していなければ、材質には自由が残る。

外の主体が内部を見なくてよいことと、内部の主体に契約があることは両立する。内部自由を用いて下位の契約を作ることができ、その下位契約にも自由な内側がある。

**下位のまとまりを再定義しても、上位に対しては同じ契約を履行する内部変更にとどまる場合がある。** 時計の内部を機械式からデジタル式へ変えても、時計塔としての契約を維持できる場合がその例である。その場合も、変更される下位契約の合意や、既に定められた変更条件は、当該契約に即して扱う。

内部自由は契約上の自由であり、実現可能性とは別に捉える。上位契約が方式を規定していなくても、物理的・技術的・制度的条件によって現実の選択肢が一つに限られる場合はある。その事実によって、上位契約がその方式を規定していたことにはならない。

下位契約や他の存在との契約が制約を持つ場合もある。内部自由は、**どの主体のどの契約に対して、何が規定されていないか**に相対的である。実態上の実現可能性と他の契約への適合は、それぞれの条件や関係に照らして扱う。

各存在が独立した意味を持ち、その内部に自由を持つこと自体に価値がある。変更の局所化や交換の容易さ、効率・生産性は、その構造が適切に成立した結果として得られ得る。

<a id="chapter-4"></a>
## 4．相互作用と実態

<a id="d4-1"></a>
### D4.1 相互作用にも意味が定義される

まとまり同士の相互作用も、主体による仮想的な定義の対象になる。同じ音でも、ある主体には騒音、別の主体には警報としての関わりになる。その関わりを、空気の振動、装置の出力、危険の通知など、異なる高さと意味で捉えられる。

現実の実態間には電気信号や音などの作用が生じる。主体はその作用を何として利用するかを定義し、意味ある関係として扱う。**新しい意味ある相互作用を成立させるには、その関わりの定義が必要である。** これは、既に起きている物理的作用一般の存在条件とは区別される。

<a id="d4-2"></a>
### D4.2 定義・運用・実態の関係

主体内の定義・命名・契約・本質・境界は仮想であり、それを表現する紙上の文書やPC上のデータは実体である。外部記録を読み、主体が認識の撮影によって捉えると、その記録についての情報Pが主体内に成立し得る。文書を作成・保存したことと、その内容を主体が認識したことは別の問いである。

**契約と実体の関係は、主体が何らかの存在をまとまりとして定義するあらゆる場面に及ぶ。** 時計、マグカップ、人物、組織、仕様書、開発環境、開発対象などを扱える。その関係は、対象を構成するまとまりや対象を表現する媒体にも、それぞれの主体と定義に応じて再帰的に成立し得る。

契約が実体に先行する場合も、実体が先に存在していて後から特定のまとまりとして撮影・定義される場合もある。契約の存在、契約の成立、対応する実体の存在、契約の履行は、それぞれに捉える。

**運用とは、定義に形作られた主体の行為・相互作用の流れであり、実体はこの運用を通じて定義と関わる。** 定義された契約は、主体の行為や相互作用を通じて実体の成立・変更に関わり得る。定義と実体は異なるため、仮想側の定義だけで実態が自動的に変わり、履行されるわけではない。

主体が契約と実体の対応を捉える際も、認識の撮影を介する。その撮影は不完全・誤り得るため、**主体が乖離を認識したことと、実際に契約と実体の乖離が存在することは同じではない。** 主体は得られた情報に基づいて関係を判断し、必要に応じて撮影を深め、定義を見直す。

実体に直接触れ、作用や体感を経験することと、その実体について思考・言及できる情報Pを成立させることは区別する。情報Pによって捉えた実体の状態と、認識内容そのものも区別する。

実態を変えずに仮想的なまとまりを捉え直せる一方、実態の変化が仮想的な本質を自動的に変えることもない。仮想的な定義と実態の対応は、**どの主体が定義した、どの契約との関係か**を特定して扱う。乖離への対処は[第6章](#chapter-6)で説明する。

<a id="d4-3"></a>
### D4.3 共有実態と共通契約

同一の実態を、異なる主体がそれぞれ別の仮想的なまとまりとして扱える。Aが棒を日時計、Bが目印として契約している場合、Bが目印としての境界を保って照明を追加しても、Aには影が利用できなくなり、日時計の契約との乖離が生じ得る。

この場合、変化した実態と、それぞれの契約との対応が異なる。Bの契約がAの契約を直接書き換えたわけではない。各主体は認識された情報を契約の意味と照らして判断するため、判断の対象となる実態と、判断に用いる情報も捉え分ける。

別々のまとまりが同じ実態を共有することを避けられるなら、その方が競合を扱いやすい。資源などの事情から共有が必要な場合は、**初めから、その共通利用を契約として定義する。** 双方が「日時計としても使える目印」として合意することがその例である。

変更範囲は、共有実態に対する各契約の内容・関係・履行への影響に照らして捉える。一つの契約内に収まる変更も、他の契約の履行へ影響する場合がある。共通利用の具体的範囲は当該契約が定め、合意形成・相互確証の運用は開発方法論が担う。

<a id="chapter-5"></a>
## 5．境界面理論

<a id="d5-1"></a>
### D5.1 問いは、幅のある再帰的構造をどのように区切るか

主体・欲求・責務を再帰的に捉えられるとき、どの幅を扱い、その内側をどの粒度と構造で区切るかが問われる。同一個体がどの高さまで主体として関わるかも、この構造の選定に含まれる。

マクロ側の起点は[D2.4](#d2-4)の基点主体とその直接的欲求によって相対的に定まり、ミクロ側の接点は各枝で異なる。分割の停止位置は、この幅のある構造を選定する中での局所的な判断である。

**境界は、基点主体が求める全体の抽象的な意味から、下位の意味と責務へ向けて選定する。** 時計を求めるなら、時計の意味を基点として計測や表示などを考える。具象の最小要素を積み上げることを、扱う意味や境界の起点にはしない。基点を捉え直す場合や再定義の判断範囲を広げる場合は、[D6.3](#d6-3)に従い、捉え直した全体の意味から選定する。

<a id="d5-2"></a>
### D5.2 境界の双璧

再帰的な分割の幅には、実践上、二つの異なる根拠による壁がある。これを**境界の双璧**と呼ぶ。

| 壁 | 幅を限定する根拠 | 例 |
| --- | --- | --- |
| マクロ側の壁 | 主体の欲求によって自然に限定される、今回作成・開発・規定したい親のまとまり | 時計を作る、ゲームを開発する、会社の規則を制定する |
| ミクロ側の壁 | 外部の存在へ委譲・依存でき、その内側を自ら構成せずに済むこと | 市販のばねやねじ、既存のプログラミング言語、既存の法律 |

マクロ側は今回の欲求の親を、ミクロ側は利用する存在への接続を与える。基点主体は現在のコンテキストに応じて選ばれ、ミクロ側の壁より下にも、その存在を担う別の主体にとっての構造が続く。

双璧の位置は捉え直せる。市販部品で足りなければ部品を自作し、既存エンジンで足りなければエンジン開発を引き受けることがある。時計への欲求に目印への欲求が合成されれば、親のまとまりが時計塔になることもある。

ミクロ側への委譲・依存には、作業委託、部品利用、既存制度を前提にした規則の制定など、異なる関係がある。共通するのは、今回の主体がその存在自体をさらに構成・制定せずに利用し、自ら引き受ける範囲を限定する役割である。物理的な内部部品だけに限らず、すべての外部制約を一律にミクロ側へ置く規則でもない。

**ミクロ側の壁の位置は枝ごとに異なる。** ある枝では幹に近い場所で責務を委譲し、別の枝では内部を細かく構成した先で接続してよい。ゲーム開発なら、ステージ制作はその単位で委譲し、アルゴリズムはゲームエンジンの提供範囲より深く実装して、プログラミング言語のランタイムを依存先とすることもできる。どこまで自ら担うかは、必要に応じて枝ごとに見直せる。

<a id="d5-3"></a>
### D5.3 幅と粒度を分けて考える

基点主体によるマクロ側の範囲と、各枝の委譲・依存先から扱う幅を捉え、その内側をどの粒度で分割するかを考える。粒度には、枝や場所ごとの粗密があってよい。

1000をマクロ側、100をミクロ側の壁とするOwnerの数値例では、同じ幅にも次の区切り方がある。

| 同じ1000〜100の幅 | 内側の区切り方 |
| --- | --- |
| 例A | 1000〜800を一つの区間とし、800・700・600・500・400と区切り、400から100の存在を直接利用する |
| 例B | 1000〜500を区切らず、500〜200を50刻みで区切る |

これらの数は抽象的な高さを説明するもので、行数・工数などの実測尺度ではない。各枝で異なる幅・粒度を選べるため、100という壁を樹全体へ固定する意味もない。中間階層をすべて独立させず、あるまとまりから委譲・依存先へ直接接続することもできる。

幅の選定と、その中の粒度の選定は異なる判断である。幅が同じでも区切り方は複数あり、粒度の検討から壁を見直す必要が明らかになる場合もある。

<a id="d5-4"></a>
### D5.4 各階層自身の責務に立つ分割判断

分割は、**その階層自身の欲求・意味・責務・構造に立って判断する。** その主体も、自身の開発を扱うコンテキストでは基点主体となり得る。判断する立場と対象範囲は現在の欲求・責務に即して捉え、個人開発という事情、全体の規模、現在の実装の密結合だけを理由に必要な責務の独立を省略しない。

**契約による分割を既定として検討し、分割しないことには意味上・構造上の正当な理由を求める。** これは、双璧の内側を区切る際の普遍的な規範的判断指針である。分割可能性という事実だけから、その義務を論理的に導くものではない。

指針の根底には、**それぞれの責務が独立した意味と責務を持つ存在として成立し、その内側に自由を持つこと自体の価値**がある。[D1.2](#d1-2)のとおり、Aを命名・契約として定義することは、NotAとの差異と境界を定め、他と区別された存在としてAを確立する。独立性はこの境界の確立に根拠を持ち、物理的な分離や他の存在との無関係さを意味しない。

契約によって複数の存在がそれぞれ何を担うかを確かにできるなら、まず独立したまとまりを成立させる方向を検討する。変更容易性や交換可能性は、独立性と内部自由が適切に成立した結果として得られ得る。分割数を増やすことや変更容易性だけを、その目的としない。

ある責務を独立したまとまりとして捉える意味があるか、自らの契約として責務を引き受けられるか、各まとまりの内側にも自由が成立するかを考える。同時に、一体として担う積極的な理由があるかも問う。ねじの頭部とねじ部に独立した責務・契約として扱う意味がなく、互いの内部事情に深く関わって一つのねじの責務を果たすなら、一体として扱う理由がある。

**分割圧は独立した責務を成立させるべき意味・構造から、統合圧は分割によって独立や内部自由が阻害される関係から捉える。** 現在の実装が絡み合っているという事実だけでは統合を正当化できない。密結合した現状でも、意味・責務に照らして独立して成立させるべきまとまりがあれば分割を検討する。

契約は意味と責務を定めることで一定の制約を伴う。その制約が独立した責務と内部自由の成立にどう関わるかを問い、どの主体のどの欲求・責務に対して分割や統合が正当かを明らかにする。

これらは普遍的な判断観点であり、個別の分割位置を一意に算出する公式や固定順序ではない。具体的な分割・統合、停止位置の選定、評価と検証は、プログラミング、文書、組織、製品などの実態・制約・担い手に応じて、開発方法論が実現する。

<a id="d5-5"></a>
### D5.5 分割停止・委譲・外から見る範囲

分割停止は、その階層の内部をさらに独立した契約へ分けず、一体の内部として引き受けることである。既に区切られた責務を別主体へ任せる委譲とは区別する。

また、PC利用者がGPU内部の回路を直接扱う必要がなくても、回路を扱う内部の主体には固有の契約がある。外の主体から見る範囲と、内部で成立する契約の範囲を捉え分ける。

この違いを踏まえ、枝ごとに独立して区切る場所、一体として担う場所、委譲・依存先へ接続する場所を構成する。委譲・依存先を担う別主体にとって、その存在は新たな基点となり得る。

境界は、時間・欲求・契約の不備・実態との乖離に応じて再評価される。判断指針に従って構造を選ぶことと、全対象・全時点について唯一の最適分割が機械的に定まることは別である。

<a id="chapter-6"></a>
## 6．乖離と再定義

<a id="d6-1"></a>
### D6.1 起点は、仮想側と実態側の乖離である

内部自由の範囲で実態が変わり、仮想側の定義と実態が対応し続けるなら、同じ契約のもとで扱える。変化そのものと、契約と実態の乖離は区別する。

主体が撮影し直し、過去とは異なる情報Pを成立させた場合は、その差異と、それぞれの主体・定義・契約を捉える。撮影は不完全・誤り得るため、どちらかの認識が実体を100%完全に表現していることを前提にしない。必要な確認方法は、対象領域の方法論で扱う。

**仮想側と実態側の乖離を認識した場合は、そのまま流さず、どの主体のどの契約に対する乖離かを特定して対処する。** 認識の不完全さを含めて撮影を深め、契約と実体の対応を扱う。

**仮想側と実態側が乖離した場合には、再定義することが望ましい。** 再定義は境界を区切り直す重要な対処である。一方、既存契約を維持して実態を修正し、乖離していない状態にできるなら、再定義は必要ない。再定義を唯一の対処としたり、実態修正が不可能な場合だけに限定したりする一律の順序は定めない。

再定義は大きなコストと影響を伴うからこそ、境界は堅牢に保つ。現在の欲求、契約の意味、実態の変更可能性と影響を踏まえ、再定義または境界を保った実態修正によって乖離に対処する。

<a id="d6-2"></a>
### D6.2 乖離・再定義の検討につながる事情

定義と実態の対応を見直す契機には、仮想側と実態側の変化がある。Ownerが示したA／B／Cは、その事情を捉える例である。

| 分類 | 事情の例 |
| --- | --- |
| A：仮想側 | A-1：時間経過や主体の変化によって欲求が変わり、適切な契約・定義が変わる。A-2：当初の定義の不備が明らかになり、本来の欲求により沿った定義が見えてくる |
| B：実態側 | B-1：調整・変更の蓄積によって実態が定義から逸脱し始める。B-2：依存先が利用できなくなったり、実態側の不備により変更を迫られたりする |
| C：双方 | AとBが混成し、双方の事情が関係する |

これらは原因を尽くす分類ではない。また、この事情が生じたことと、成立済み契約と実態の乖離があることは別に確かめる。

欲求の変化を扱うときも、[D4.2](#d4-2)に従って、どの主体のどの定義・契約との対応かを特定する。成立済み契約には実態が対応していても、現在の新しい欲求に応じた定義候補には、その実態が適合しない場合がある。

分単位の時刻表示を履行する時計へ、秒単位の表示を新たに求めたとする。旧契約の履行、新しい定義と実態の適合、その内容についての合意の成立はそれぞれに捉える。新しい欲求は、新しい本質を定義する契機となり得るが、それだけで旧契約の意味や履行状態を遡って変えたり、新しい合意を成立させたりはしない。

欲求と既存定義の差、定義候補と実態の関係、成立済み契約と実態の関係を区別する。依存先が契約を履行していない場合と、履行しているが現在求める能力には足りない場合も、この区別で捉えられる。

<a id="d6-3"></a>
### D6.3 再定義は境界を区切り直す行為である

再定義は、何を一つの存在として扱うかという境界を区切り直す行為である。名前＝本質＝境界が一体であるため、その存在として担うことや、他の存在からの扱われ方にも関わる。

区切り直しは大きなコストと影響を伴うため、**境界は堅牢に保つ。** 内部の都合によって成立した意味をなし崩しに変えず、契約を履行する範囲で実態を変更する内部自由を持つ。

必要な区切り直しは、まずその階層自身の主体で判断する。そこで扱えなければ親の主体へ、さらに必要ならその親へと判断する高さを上げる。

[D3.4](#d3-4)の内部自由により、下位を再定義しても上位の意味と契約を維持できる場合がある。上位の契約を維持できない場合は、その上位での再定義も検討する。これは、上位を常に不変にすることや最小変更を常に選ぶことを別の規則として加えるものではない。

判断の高さと、変更される契約関係の合意の範囲を捉え分ける。必要な範囲は、どの契約内容が変わり、どの関係の履行へ影響するかによって考える。上位の再定義が不要な場合も、下位契約や共有実態を介する別の契約との関係は扱う。

変更後の合意は[D3.2](#d3-2)、共有実態への影響は[D4.3](#d4-3)に従う。合意形成・相互確証の運用と権限の具体的配置は、開発方法論が担う。

<a id="d6-4"></a>
### D6.4 欲求への立ち返りと定義の脱皮

現在の主体は、その存在に何を求めているかへ立ち返り、より適切なまとまりを定義し直せる。

Aが日時計を使いたいのは時刻を知るためであり、Bが目印を使いたいのは迷わないためである。日時計や棒という現在のまとまりから、時計塔という別の本質へ脱皮できる。電話からスマートフォンへの変化も、新しい意味と契約を見出す例として捉えられる。

脱皮は、主体が自分の欲求をどの高さ・範囲で捉えるかを見直すことに基づく。既存の名前や実現形態に固執せず、定義の不完全さや変化を含めて捉え直す。第三者が推測した隠れた欲求を正解として置くこととは異なる。

脱皮には、まとまりの解体・再構成も含む。捉え方が横へ移ったときは、その位置で扱う幅と内側の境界を再び考える。新たな欲求や依存可能性によって双璧の位置も変わり得る。現在の境界選定に、将来のあらゆる再定義を同時に織り込むことは要しない。

再定義の前後で同じ存在かを問う際も、どの主体が、どのまとまりの、何の意味を同じとして扱うかを特定する。同じ実態や履歴が続いていても定義が変わる場合があり、ある定義が変わっても別のまとまりでの連続性を保つ場合がある。

旧契約の継続・変更・終了は、その契約の内容と関係、合意に即して扱う。新たな定義を設けても、旧契約を別のまとまりとして維持する構成はあり得る。再定義だけで旧契約の終了・継承・改訂が自動的に決まるものではない。
