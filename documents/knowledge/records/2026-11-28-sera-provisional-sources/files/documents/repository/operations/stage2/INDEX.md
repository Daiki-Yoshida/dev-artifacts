# Stage 2　SERA開発哲学の判断記録と調査資料

**SERA開発哲学（セラ）**は、主体を起点に環境・記録・実現を考える四つの哲学の総称である。S・E・R・Aの文字順は、第一SCB、第二EIC、第三RTC、第四AJFの番号順に対応する。四体系の真名・責務、および今回の総称・番号・実現の英語と略名の採用は、[体系構成](../../../knowledge/subjects/dev-philosophy/INDEX.md)と[SERAの採用記録](../../../knowledge/records/2026-11-26-sera-philosophy-naming-and-order/RECORD.md)から辿れる。

2026-11-26の[四哲学の仮決定記録](../../../knowledge/records/2026-11-26-sera-provisional-adoption/RECORD.md)に基づき、四体系の本文は[開発哲学の仮決定版](../../../knowledge/subjects/dev-philosophy/INDEX.md)に置いた。この作業資料領域は、各体系の出典、草案を推敲した経緯、監査時点の所見を保持する。記述・分析・Ownerレビューは日本語を標準とする。[四体系を定めた2026-11-20の判断](../../../knowledge/records/2026-11-20-four-philosophy-systems-adoption/RECORD.md)

## 仮決定版と出典対応

### 1．主体と契約と境界の哲学（SCB哲学）

[本文](../../../knowledge/subjects/dev-philosophy/SCB.md) / [用語索引](../../../knowledge/subjects/dev-philosophy/SCB_GLOSSARY.md) / [出典・レビュー](A3_PHILOSOPHY_REVIEW.md#review-status)

責務範囲は主体。あらゆる存在に対する思考の根源として、主体が意味あるまとまり・責務・関係を定義する基礎を担う。第0章と六章、既存D番号を維持して本文を整えた。認識、欲求と本質、契約・成立・履行、内部自由、境界選定、乖離と再定義を扱う。

<a id="4環境と独立と制御の哲学eic哲学"></a>
### 2．環境と独立と制御の哲学（EIC哲学）

[本文](../../../knowledge/subjects/dev-philosophy/EIC.md) / [出典・レビュー](A3_STATE_CONTROL_REVIEW.md)

責務範囲は環境。SCBのまとまりとして環境を定義し、独立・依存と境界に相対する清潔さ・汚染、環境を通じた行為の命名、提供を引き受けた行為の契約と公布、環境の構造による履行と安全性、再現活動の環境を五節にまとめた。内部自由と境界での堅固な契約の履行を結び、再現・管理と包含の関係を区別する。真名・略名は確定し、個々の定義の文章・語彙は引き続き吟味する（[清潔さ・行為の契約・再現環境に関する判断](../../../knowledge/records/2026-11-24-environment-cleanliness-actions-and-reproduction/RECORD.md)）。

<a id="2記録と真実と伝達の哲学rtc哲学"></a>
### 3．記録と真実と伝達の哲学（RTC哲学）

[本文](../../../knowledge/subjects/dev-philosophy/RTC.md) / [出典・レビュー](A3_TRUTH_SOURCE_REVIEW.md#review-status)

責務範囲は記録。当時の表現へ立ち返れることと、後の主体が意味を適切に理解・判断・利用できることを一体で担う。原本と解釈、主体としての記録、逐次記録、評価・訂正、再開を支える説明、適切な伝達とNALを扱う。

<a id="3実現と判断と充足の哲学rjf哲学"></a>
### 4．実現と判断と充足の哲学（AJF哲学）

[本文](../../../knowledge/subjects/dev-philosophy/AJF.md) / [出典・レビュー](A3_PURPOSE_NECESSITY_REVIEW.md)

責務範囲は実現。AJFは Actualization / Judgment / Fulfillment の頭文字である。実現を表、判断を裏とし、主体がなぜその行為を選んだか、その働きかけが何を満たしたかを扱う。「意思と判断」「必要と選択」「充足と判断の更新」の三節に整理し、採用済みのAONは第2節に置く。第3節では、個々の契約が履行されたとき、全体の目的を満たすには何が必要かを[乗り継ぎの例](../../../knowledge/subjects/dev-philosophy/AJF.md#parts-and-whole)で検討する。

## 原文と編集の扱い

[Philosophy Baseline](PHILOSOPHY_BASELINE.md)は、Ownerとの直接対話を優先的に辿るための索引である。現在の構成と、その後の継続判断へ案内する。原文・採用・訂正・提案の違いは、各recordのsource inventoryと各体系のレビューで確認する。

本文は現在の意味とその理由を直接説明し、過去の訂正や構成変更の経緯はレビュー・records・Git履歴から辿れるようにする。NALに配慮しつつ、意味に必要な条件・規範の強さ・例・反例・対比を保持する。原文payloadを現在の説明へ合わせて書き換えない。

## 2026-11-25の振り返り

以下は、11月25日に当時の四つの本文とレビューを照合した編集上の所見である。当日の「RJF」は現在の第四哲学（AJF）に当たる。[当時の固定版](https://github.com/Daiki-Yoshida/documents-artifacts/blob/3ca5ca1fc70495dd7578054bbcffd994d77538e5/documents/repository/operations/stage2/INDEX.md#review-2026-11-25)

SCBでは、契約を誰がどこまで引き受け、誰に委ねたかを説明できる。RJFはそこから、各主体が引き受けたことを果たしたとき、全体として求めた意味が実際に満たされたかを問う。乗り継ぎの例では、各区間が予定どおりでも接続条件次第で到着期限を守れない。旧資料から抽出した「境界をまたぐ成果の調整」は、この関係としてRJFの第3節に入っている。[SCBのレビュー](https://github.com/Daiki-Yoshida/documents-artifacts/blob/3ca5ca1fc70495dd7578054bbcffd994d77538e5/documents/repository/operations/stage2/A3_PHILOSOPHY_REVIEW.md#review-status)・[RJFの本文と出典の対応](https://github.com/Daiki-Yoshida/documents-artifacts/blob/3ca5ca1fc70495dd7578054bbcffd994d77538e5/documents/repository/operations/stage2/A3_PURPOSE_NECESSITY_REVIEW.md#traceability)

活動を再開する場面では、RTCによって後の主体が当時の判断と残る仕事を読み取れる。EICによって、当時の活動を支えた依存関係と状態を捉え直し、再開に必要な環境を再び成立させられる。記録を読めても当時の依存先を利用できない場面を考えると、この二つの責務を別々に確かめられる。[RTCのレビュー](https://github.com/Daiki-Yoshida/documents-artifacts/blob/3ca5ca1fc70495dd7578054bbcffd994d77538e5/documents/repository/operations/stage2/A3_TRUTH_SOURCE_REVIEW.md#review-status)・[EICの草案](https://github.com/Daiki-Yoshida/documents-artifacts/blob/3ca5ca1fc70495dd7578054bbcffd994d77538e5/documents/repository/operations/stage2/A3_STATE_CONTROL_DRAFT.md)

SCBでは過去に検討した反例まで現行の定義で説明できるか、RTCでは原本・意図・後の解釈の関係をどこまで原文に忠実に説明できているかが通読の焦点となる。RJFでは選択の根拠、実際の充足、そこへの主体の寄与を読み分けられるかを吟味する。EICでは「汚染」がどの境界でどんな作用を指すのか、語彙と定義文の最終吟味が残る。
