# 文書と記録の方法論〈仮称・草案〉

判断や観察が生じたらその時点の**記録**を残し、それで読者の行動が変わるなら、読者が普段開く**現行文書**を更新する。後から「今はどうするか」と「当時なぜそうしたか」の両方を、必要とする人が確かめられる形で手渡す。[RTC哲学](../../dev-philosophy/RTC.md)

用意するのは、記録を必要な期間保存できる場所と、読者が資料とその版を特定して開ける手段。共有フォルダなら文書名・日付・版、Gitで管理する場合はファイルのパスとコミットが使える。会議の決定を施設案内に反映する担当者も、個別のWorkを作らずに以下の手順を使える。

## 1. その場で一件残す

判断した人や観察した人が、判断・検証・中断のひと区切りで、後から必要になることを記す。別の人が記録するときは、誰の発言・観察かを示す。長時間区切りが来なければ、そこまでの確認結果と未解決の問いを保存して続ける。

- **決定なら**、誰がいつ、何を対象に、何を理由に決め、いつから使うのかを書く。提案を受け取っただけなら、誰の決定を待っているかを残す。
- **観察なら**、確認した資料や対象の版、条件、実際に見た結果を書く。報告を受けたこと、自分で確かめたこと、原因の見立てを読み分けられる言葉を使う。続きを託すときは、残件と次に確かめる対象を一文添える。
- 後の判断を左右する原資料には、版や該当箇所まで戻れる参照を添える。消える会話や差し替わる添付にしか原文がない場合は、保存と共有の権限の範囲で必要な箇所と文脈を残し、抜粋・伝聞・未確認の別が分かるようにする。

**記入例（架空）**　「4月2日、施設責任者が、清掃員の入館時間に合わせて4月の土曜の開館を9時から10時に変更すると決定。日曜は従来どおり。根拠は運営会議の4月2日決定欄。受付の掲示は差し替え待ち。」この程度の案件なら、議事録の該当箇所をそのまま判断の記録として指せる。日々の経過に固定の帳票は要らない。[逐次記録の提案原文](https://github.com/Daiki-Yoshida/dev-artifacts/blob/7c9468ed4c8270c156b930d94ea6335a14856985/documents/knowledge/records/2026-10-13-work-records-proposal/USER_MESSAGES.md)

## 2. 読者が使う場所を更新する

読者の入口から、変更対象の案内を見つける。既存の担当文書に、新しい内容と適用範囲・開始時点を反映する。新しい文書が必要なら入口にも追加する。判断の記録は保守する人が辿れる場所から参照し、外向けの案内には利用者の行動に必要な情報を載せる。採用が決まっていない案や、観察しただけの仮説は記録に保持する。[既存の文書管理の正本](https://github.com/Daiki-Yoshida/dev-artifacts/blob/7c9468ed4c8270c156b930d94ea6335a14856985/documents/knowledge/subjects/documentation/INDEX.md)

例の施設なら、来館者が見る「開館時間」の4月の土曜欄を10時に更新し、受付用の掲示も差し替える。案内を保守する人向けの更新履歴には、決定欄の位置を添える。Webを更新して掲示は旧版のままなら、経過には「Web反映済み、掲示は担当へ依頼中」と書ける。

## 3. 誤記を訂正する、新しい決定を反映する

後から違いが見つかったら、まず原資料の該当箇所と照合する。何が違ったかで手順が変わる。

| 判明したこと | 残すものと更新するもの |
| --- | --- |
| 決定欄は「土曜」だが、公開案内に「日曜」と転記していた | 誤記のあった版、決定欄、訂正した箇所を記録し、案内を直す。以前の表示を確認する必要がある人のために、その版か写しを辿れるようにする。 |
| 4月16日に、以後は日曜も10時とする追加決定があった | 追加決定の主体・適用日・対象を新しく記録して、先の決定を参照する。現行案内に適用日を記し、4月前半を調べる人には当時の案内と根拠を残す。 |

## 4. 次の人が開けることを確認する

案内した入口から、読者が使う版を開き、変更した値と適用範囲を読む。次に、保守担当が使う入口から判断時の原資料を開き、該当箇所が分かるか確かめる。引継ぎであれば、相手が未確認事項と次に開く資料も特定できるかを見る。閲覧先が非公開なら、関係者が利用できる権限の範囲で確認する。

記録を別フォルダや保管先へ移すときは、移管元の一覧・内容と移管先を照合し、参照を直して移管先から開き直す。同名で内容が異なる場合や一部しか読めない場合は元と先の双方を保持し、何が未確認かを記す。Workでの引継ぎ・終了には、この保存・参照の確認結果を返す。[移管に関する採用判断](https://github.com/Daiki-Yoshida/dev-artifacts/blob/7c9468ed4c8270c156b930d94ea6335a14856985/documents/knowledge/records/2026-10-13-work-records-implementation-adoption/RECORD.md)
