# 文書と記録の方法論〈仮称・草案〉

会議で決まったこと、試して分かったこと、途中で見直した判断を、その時点で残す。そこから、今の読者が行動するための文書を整える。**「今日どうすればよいか」を知りたい人と、「その時点で何を根拠にそうしたか」を調べる人が、それぞれ答えに着けること**がこの方法の目的である。[RTC哲学](../../dev-philosophy/RTC.md)

使うものは、必要な期間残せる記録場所と、受け手がそこにある資料の該当箇所・当時の版を特定して開ける手段である。以下では、施設の開館時間が変わる一件を、担当者の共有フォルダと来館者向けの案内を使って扱う。

## 受け取った情報の行き先を決める

**原資料**は、判断や観察の出どころを直接確かめられるものを指す。決定者本人の回答、測定結果、会議で確定した議事録などがこれに当たる。**記録**は、ある時点で誰が何を決め、あるいは確かめたかを後からたどるために残す。**現行文書**は、その主題について今有効な内容を読者に伝え、担当者が更新する文書である。同じ出来事からどれを作るかは、次の人が何に使うかで選ぶ。

| 受け取ったもの | 担当者の判断 |
| --- | --- |
| 「土曜は10時開館にしたい」という提案 | 判断が次回に持ち越されるなら、提案者と理由、誰の判断を待つかを記録する。来館者には現在有効な時間を案内する。 |
| 施設責任者の「4月の土曜は10時開館にする」という決定 | 決定欄を根拠として保存し、来館者が使う案内と受付の掲示を更新する。決定欄に必要な文脈が揃っていれば、それが判断の記録を兼ねる。 |
| 担当者が「案内ページは10時、受付の掲示は9時」と実際に確認した結果 | 見た場所と時点、食い違いを記録し、残る掲示の更新を引き継ぐ。開館時間を決めた根拠には先の決定を使う。 |

一行で後の担当が同じ判断を確かめられるなら、その一行で足りる。回答が「その案で」のように短い場合や、後日資料が差し替わる場合は、対象となった提案・版・該当箇所も残す。その時にしか取れない原文や観察結果を先に保存すると、後で説明を直せる。

## 最初の一件を残す

1. **読者と置き場所を決める。** まず「変更を知ったら何をする人か」を一人具体的に挙げ、その人が普段見る案内と、担当者が判断の経緯を読む場所を探す。すでに運営会議の議事録と施設案内があればそこを使う。どちらもなければ、担当者が共有できる場所に日付付きの記録を一件作り、案内が必要なときに読者の入口へ置く。共有フォルダなら、たとえば担当者向けの `運営/記録/2026-04-02-開館時間` と、来館者向けの「施設案内 → 開館時間」で始められる。
2. **当時の判断を残す。** 決定なら誰が、いつ、どの範囲について何を理由に決めたか。検証なら誰が、どの版や条件で何を観察したか。別の人から聞いた結果には報告者を、自分の見立てにはその根拠を添える。未確認なら、確認できた範囲と次に見るものを書く。
3. **後から同じ資料を開けるようにする。** 判断に使った記録の場所を、日付・文書名・該当の節などと一緒に示す。版を管理する仕組みがあれば、その時点の版へリンクできる。元資料が消えるおそれがあるときは、許された範囲で写しを保存し、原文の範囲と、記録者が補った説明を読み分けられるようにする。非公開の資料は、それを読める担当者の場所から参照する。

**記入例（架空）**

> 4月2日・受付担当記入。施設責任者が、清掃員の入館時間に合わせて4月の土曜を10時開館と決定。日曜は従来どおり9時。根拠は「運営会議／4月2日議事録／開館時間」の決定欄。施設案内と受付の掲示は更新待ち。

判断を変えたとき、検証を終えたとき、中断・交代するときも同じように残す。長い作業で区切りが来なければ、分かったことと残る問いをその場で短く書き足す。一つの記録に関連する複数の経過をまとめられる。[逐次記録の提案原文](https://github.com/Daiki-Yoshida/dev-artifacts/blob/7c9468ed4c8270c156b930d94ea6335a14856985/documents/knowledge/records/2026-10-13-work-records-proposal/USER_MESSAGES.md)

## 今の読者に届け、担当を引き継ぐ

主題を担当する人は、決定で行動が変わる読者と媒体を確かめ、既存の案内に適用期間・対象・変更内容を書く。例の来館者には「4月の土曜日は10時開館です。日曜日は9時開館です。」で用が足りる。保守する人には、どの記録を使って案内を書き換えたかを更新履歴などから示す。新しく案内を作った場合は、読者が普段開く目次や案内ページからも辿れるようにする。[文書の配置と保守に関する既存正本](https://github.com/Daiki-Yoshida/dev-artifacts/blob/7c9468ed4c8270c156b930d94ea6335a14856985/documents/knowledge/subjects/documentation/INDEX.md)

途中で担当を交代するなら、現物を見た時点の状態を記録する。たとえば「施設案内は更新して公開ページで確認済み。受付の掲示は9時のまま。次の受付担当が決定欄と照合して掲示を差し替える」。後任はこの記録から現在の掲示を確認し、差し替え後に来館者の位置から時間を読んで結果を追記する。これで、読者は案内から開館時間を、保守担当は記録から根拠と反映済みの媒体を確かめられる。

## 訂正と移管

| 後から起きたこと | 行う操作 |
| --- | --- |
| 公開案内に「日曜10時」と転記していた | 決定欄と照合し、誤記のあった版・訂正箇所・根拠を記録して案内を直す。過去の案内を確認する人にはその版か写しを示す。 |
| 受付担当が残した当日の記録自体に「日曜」と書き誤っていた | 決定した当人の回答や議事録の決定欄に戻って照合する。元の記載を当時のものとして読める形で残し、そこから辿れる訂正に、訂正日・訂正者・正しい対象・根拠を書く。その誤記を使った案内も確かめ、影響した箇所を直す。 |
| 4月16日に、以後の4月の日曜も10時開館と決まった | 新しい決定者・対象・適用開始日を記録し、前の決定を参照する。現行案内に新しい適用期間を反映する。4月前半の問い合わせには当時有効だった決定を使える。 |
| 記録を共有先から長期保管先へ移す | 元の内容を保って移管先に保存し、一覧・本文・必要な添付を照合する。担当者の入口から参照を張り直し、必要な版と根拠を開けるか確かめる。同名の別資料がある、保存が途中、または後任から読めない場合は両側を保持し、未確認箇所と次の対応を記録する。 |

一つの目的を引き受けて開始から終了まで扱う作業単位を[Work](../work/INDEX.md)という。Workで本方法を使うときは、保存した記録の場所・確認できたこと・残件を担当者に返す。どの時点でその仕事を閉じられるかはWork方法論が定める。[移管に関する採用判断](https://github.com/Daiki-Yoshida/dev-artifacts/blob/7c9468ed4c8270c156b930d94ea6335a14856985/documents/knowledge/records/2026-10-13-work-records-implementation-adoption/RECORD.md)
